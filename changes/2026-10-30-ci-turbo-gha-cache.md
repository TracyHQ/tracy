- **Tracy CI's Turbo remote cache lives on the repository's GitHub Actions cache instead of Cloudflare R2, with no secret; hosted pull requests restore the pnpm store that one nightly job saves** — hano-xbt (Claude) · `ci-gha-turbo-cache` · 2026-10-30
  **Affects:** whoever reads a Tracy CI run. The four `TURBO_CACHE_S3_*` secrets were never set on this repository, so the cache never started: every run planned as if nothing were cached ("secrets are not set") and the nightly fell back to the workers shards, writing nothing. `scripts/ci/turbo-cache-server.mjs` now speaks the Actions cache service v2 (one entry per artifact, `turbo-<team>-<hash>`), started by `.github/actions/turbo-cache`, now a `node24` action because only JavaScript actions receive `ACTIONS_RUNTIME_TOKEN`. The cache starts on every event; the nightly's forced Turbo rows write under `main`, which every pull request reads, so a routine pull request into `develop` can skip rows from the next nightly on. A pull request writes under its own scope only; a fork's would be read-only. `.github/actions/dsh-lib/hosted-pnpm` no longer saves on a pull request (~870 MB per pull request scope): pull requests restore the exact key, or the newest store of the same OS, architecture and scope by prefix when the lockfile changed. A new report-only job, `save the hosted pnpm store` (`pnpm-store-seed`, `ubuntu-latest`, nightly and manual runs on `main`, `continue-on-error`), fills the workspace store with `pnpm fetch` for the nightly's pinned `develop` commit and saves it under `main` when the key is not there yet. Until the first nightly after the merge, hosted pull requests restore nothing and download from npmjs. The four secrets can be deleted.
  **Why / Measured:** the server is tested against a fake cache service (`scripts/test/ci-turbo-cache-server.test.mjs`: HEAD hit/miss, GET, PUT new and existing, a failing or unreachable service as a miss, the action's start and its read-only fork mode); `ci-hosted.test.mjs` pins that only the seed job saves the store, with the key pull requests restore. Not measured yet: the first run on GitHub (writes) and the second push (reads).
