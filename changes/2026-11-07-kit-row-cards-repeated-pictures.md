- **The kit's row pair measure gives each list row its own picture element and ignores a slider's state classes** — Joomla T4 batch 1 readiness · `feat/joomla-t4-batch-1-readiness` · 2026-11-07
  **Affects:** template preparers reading `rowPartsUnpaired` on a template kit (`template-kit/lib/read-row-cards.js`, run by `build` and the frames pass). Rows of a list that show the same demo picture now each take their own element, in order, as two text slots with the same words already did; a card's signature leaves out slider state classes (`active`, `owl-item`, `swiper-slide-*`), as `row-fix.js` does. A carousel whose shown and hidden slides used to read as a lone `block` row beside `active` card rows now reads as one kind of card. Kits built before keep their recorded `printsIn` until rebuilt.
  **Why / Measured:** JA Symphony j6 1.0.6 module 104 (gallery, six slides, four `active`, slides 1, 5 and 6 showing one picture) read rows 0, 4 and 5 as `block` and rows 1 to 3 as `DIV.active.owl-item`, so the kit held on `rowPartsUnpaired`. New browser test `test/template-kit-row-pairs.test.mjs` (carousel case) fails before the fix with exactly that pattern and passes after; `template-kit-check-accepts`, `template-kit-frames`, `template-kit-row-pairs`: 16 pass, 0 fail.
  **Also:** a looping slider's copies of its slides (`.cloned`, `.swiper-slide-duplicate`, `.slick-cloned`) are never taken for a row's picture or text while the slide itself is there — JA Vega j6 1.0.10 modules 111 and 117 read rows in `DIV.cloned` beside `DIV.` and held on `rowPartsUnpaired`. The carousel test now prints those copies and fails before this part of the fix.
