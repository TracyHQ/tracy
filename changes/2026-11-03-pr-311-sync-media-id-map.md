- **Sync to/from live: a taken live delete leaves the id map and its copy-only rows, and a pushed picture carries its own words and keeps its files when kept (#307, #223)** — David (davidd-lgtm) · #311 · `fix/sync-pushed-media-id-map` · 2026-11-03
  **Affects:** the database merge (`lib/live_sync.py`) now answers `idMapForgotten` (entries it dropped) and `counts.orphansRemoved`, keeps a taken table's AUTO_INCREMENT, and removes the copy's own rows of a record whose live delete it took (from `dependents`, the new `ownedRows`, and the entities' `names`). WordPress gains `dependents` for posts (postmeta, term_relationships): a kept post keeps them, and a table holding them is no longer taken whole. On WordPress the merge answers `keepFiles`, and `webroot-sync.sh` puts those files of kept Media Library items back into the merged tree. Sync to live has a new kind `mediaText` (kind `post`, group `files`) that writes a picture's title, slug, caption and description: after the upload for a new picture, and as an edit for an existing one. No Claude Cowork release is needed. Pictures pushed before this still lack the seed: push them again after deploy.
