- **Content map samples keep the demo's inline markup (`((br/))`, `((span))`), a new kit self-check `inlineMarkupLost` holds a kit whose map lost it, and the copy export reprints the demo's line break before an accent word** — Akemi · #370 · `feat/write-step-bench` · 2026-11-04
  **Affects:** whoever captures or resettles a Joomla contract, the template kit and the Template kit step on /ops, and the copy export. `capture-contract.py --inline-markup` (needs `--whole-units`, off by default so released profiles re-capture byte for byte) writes a whole-unit sample as its unit's markup in content map notation (`scripts/unit-markup.php`), counts `maxCharacters` on the plain text, and keeps a role across `--previous-map` when only markup changed. New `content-coverage/resample.mjs --contract <dir> --db-dump <sql> [--write]` does the same for an existing map from the installer's dump, rewriting only samples, and writes an `inlineMarkup` block into `content-coverage.json` (restamping a coverage file that was current; `restampedFrom` names the old digest). The SQL dump reader can apply the UPDATE and DELETE fixes an installer appends (`readDump(file, { changes: true })`); `normText` reads `((br/))` as a space. The kit counts `inlineMarkupLost` from that block (1 when a whole-unit map was never measured) and /ops names it "inline markup lost". The export writes `((br/))` before the wrapped emphasis when the kit slot's demo has a break right before a span that ends the text (`Our((br/))((span))Classes((/span))`), never otherwise. JA Boxing 1.0.10: 64 samples resampled, kit settled and packed again, approval unchanged.
  **Why / Measured:** the 1.0.10 content map held 63 text slots whose stored value marks words inline (section titles such as `More<br><span>Blogs</span>`, masthead titles, article headings) with plain samples, so the kit listed `inline` on 15 slots and the written site printed those titles on one line in one colour. After the resample: `inlineMarkupLost` 0, 69 kit text slots carry `inline`.
