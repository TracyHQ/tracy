- **A typed answer in the build chat is an owner statement for the writer, never a field value** -- AI quickstart work for #575 | PR pending | `feat/ai-quickstart-575` | 2026-11-16
  **Affects:** The build chat compose step. A free text answer to the main button question or to a fact conflict question no longer stops compose with `answer_invalid` when it is longer than the template's field of that kind: `settleAnswers` writes no fact for it, leaves a fact conflict open (its default shows as an assumption, as for an unanswered conflict), and adds it to `profile.ownerFacts` as `{id: "answer-<question>", group, text, question, asked, candidates?}` (new module `domain/plan-free-answers.mjs`). The page writer reads it as an owner fact to reword, with its question and a conflict's candidate values (`ownerFactView`), placed next to a writer worded main button label for the main button question. A text typed exactly as an offered choice is that choice, and a chosen option keeps its behaviour and its length rule. The main button and fact conflict questions no longer cap `freeText.maxLength` to the template's field. A typed corrected value (a third phone number, say) is no longer written as the fact by code. The release gate's marker build now chooses its marker label instead of typing it. Neither the plan composer prompt nor the page writer prompt changed. The tracy-web image must be rebuilt for the build chat to pick this up.
