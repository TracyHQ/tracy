- **Demo farm: the farm web is replaced blue/green — folding, unfolding or refreshing one demo no longer fails requests to the other folded demos (on a current-config forwarder)** — fleet operations (agent) · `demo-farm-no-blip` · 2026-11-14
  **Affects:** fleet operators folding/unfolding demos and everyone reading a folded demo meanwhile. Changing the farm web's mounts or image used to re-create `tracy-demos-web` (old container killed, new address, 1–5 failed requests per switch through a forwarder). The web is now two slots, `tracy-demos-web-a` / `-b`, both with the alias `tracy-demos-web`; the serving one is named in `<private root>/_demos/.active-web` (every exec into the farm reads it — `tracy_farm_web`, tracy-host `site-exec.js`; the docker proxy still never lets a seat exec there). A switch starts the other slot beside the serving one, marks it ready (`/tracy-ready` on port 8080 answers 200 only then), **gives every forwarder 6 s to start using it**, takes the old one out (marker removed, 5 s for every forwarder to see it, waits until idle, graceful stop, removed); a slot that never gets ready is removed and the serving one is untouched. After an interrupted switch the next apply **retires** a leftover slot the same way (never kills one that may be serving). Forwarders created from now on (current config) use `server-template` over the alias and an HTTP health check (`option httpchk`; 200 = ready, 403 = a pre-slot farm), so a new connection never reaches a slot that is about to close. New image tag `…-r4` (the base image's stop signal was never trapped; the entrypoint now drains on TERM/INT/QUIT). New `provision/farm-switch.sh` moves the farm to the checked-out image after a deploy. check-server and server-status-alert alert when running slots are all unready; they, fleet-map, deploy-tracy-stack, the updater and the image workflow know both slot names. **Not covered:** forwarders created before this change keep the old single-server config until restarted; through them a switch behaves as before (a reset window, a visible 502 behind cloudflared). **Migration of a host that still runs the pre-slot farm — forwarders first:** `provision/farm-forwarders.sh --apply` (one ~0.3 s gap per demo, at its own restart; current-config forwarders work in front of the old farm), then `provision/farm-switch.sh` (invisible). The other order gives every demo a reset window at the switch plus the restart gap afterwards. See `docs/references/demo-farm.md`.
  **Why / Measured:** a real-host probe got 1 × 502 in 108 over a fold + unfold. The first attempt (drain + haproxy retries) was refused in review; the second passed an e2e whose probe could not fail (a curl reset killed the background worker under `set -e` before it recorded `000`) and whose forwarders ignored their readiness check (`option httpchk` missing). Fixed probe, plus an independent raw-TCP probe (8 clients, static page, empty replies counted): an unfold closed 57–93 connections, found to be a 71 ms window with no server at all because the old slot was withdrawn the moment the new one was marked ready (haproxy logged the old one DOWN 71 ms before the new one UP); fixed by the 6 s up-wait. After it: 0 failures through a current-config forwarder in every phase; see the report for the counts. The probe itself is shown to go red (a farm web killed under load: thousands of failures), and the e2e fails when it leaves containers, volumes, networks or temp dirs behind.
