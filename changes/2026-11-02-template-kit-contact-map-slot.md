- **The template kit names setting slots: the map a contact page button opens, and the contact's empty mobile line, are now writable** — Claude, for Akemi · #298 · `fix/template-kit-contact-map-slot` · 2026-11-02
  **Affects:** anyone reading `template-kit.json` (the planner, /ops) or running `template-kit/cli.mjs`. A new `site.settingSlots[]` lists values a page prints from a CMS row that no content map slot holds (a released content map never changes): each has an `id`, `kind`, `writeTo` (the content map entity and column), `valueFormat` and `fillFrom`. `map-location`: a free-HTML block whose whole content is one JA Google Map shortcode (`{jamap ... locations='...'}{/jamap}`, read by the Joomla adapter from the database), written as the whole column from `writeTo.template` with an address, and latitude and longitude when a placeId gives them; a map button (`links[].opens.shows: "map"`) on a page with exactly one such block assigned now says `writable: true` and `slotId`. `contact-mobile`: a contact block's printed but empty mobile field is written through `<contact>.mobile` with the telephone line's limit (`settingSlot: true`); the coverage gate checks that every such field's slot is listed. New command `cli.mjs setting-slots --out <dir> --contract <dir> --db-command <prefix>` settles a written kit again with no browser and no image touched. The JA Boxing 1.0.10 kit is regenerated with it: the contact page's map button points at `block-164.map-location` and `contact-1.mobile` is writable; its image set and approval are unchanged.
  **Why / Measured:** every site built from JA Boxing hid the "Open in Google Maps" button and could not print a second phone. On a local site restored from the 1.0.10 installer, writing a fabricated address into the map block and a fabricated number into the mobile column shows both in the contact page HTML (the map's `locations` setting and a `contact-mobile` line). Kit self-checks all 0, 110 images byte-identical, digest equal to the approval.
