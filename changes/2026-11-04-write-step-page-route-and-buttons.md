- **Created pages take the route of the template's content pages; every visible button has an owner; a scripted link is not a dead one** — Akemi (with Claude) · #379 · `feat/new-page-and-unowned-buttons` · 2026-11-04

  The kit now records how a template presents a content page (`site.contentPages`) and lists every visible button (`blocks[].buttons`). The write step opens a created page under one hidden category menu item (alias `site-pages`) with the same layout, so it prints one main heading and nothing the template's content pages do not show; a page an earlier run gave its own menu item moves there and that item is unpublished. A plan label naming the same button on another block now also writes this block's own field, and the link is held by this block's own address. A button no plan speaks of leaves through the existing hide routes, whole or not at all. The site check gains `main-heading` (more than one blocks, none warns) and `unowned-slots` blocks when a visitor sees the slot. `cta-real` no longer flags a link that has a click handler.

  **Affects:** anyone reading the write report or the kit (new fields, new `<page>:route` lines), and the created page's public address changes to `/site-pages/<slug>`. `apps/tracy-host` must be redeployed for the new page measures; until then `main-heading` answers unmeasured and `unowned-slots` stays a warning.
