- **Write step bench, part 3: the brand file reaches the site** · Claude, for Akemi · #355 · `feat/write-step-brand` · 2026-11-04
  **Affects:** whoever runs the write step bench. `node scripts/write-step-bench.mjs run` takes a new optional `--brand-file <path>`; a copy-only run works as before. A new export, `exportBrandOrders` (`write-step/brand-write-orders.js`), turns a brand file into write orders. The new `brand` phase runs after the first site read and before the contract call: the name through `site.identity` and the site profile, logos and the favicon through `media.upload` and `template.siteSettings`, PNG 32, PNG 512 and the phone icon as link tags in the kit's head block, the accent as one Design system module through `content.update`. The name slot and the footer logo join the one contract call. The site is read again afterwards, because the head block moves the revision. Brand claims join the owner table, so a dispute with the copy stops the run with nothing written. Each brand item has a report line with `part`, `ordered` and `readFrom`. The read-back gains a `contains` read and reads a line with a `key` through inspect, even when it has a `part`. No customer-facing change: the bench calls no host job for the accent, and `site-ds-slot` is unchanged for the Design system door.
  **Why / Measured:** ADR 0044 makes the write step the only writer. Unit tests only, on a fake site door; the run on dev is still to come.
