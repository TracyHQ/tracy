- **CI moves to GitHub-hosted runners: every gate, every Tracy CI job and the image/installer build jobs run on `ubuntu-latest`; only deploys and the dev host's own jobs stay on the team's runners** — CI agent · `ci/light-gates-hosted` · 2026-10-27
  **Affects:** everyone opening a pull request: each light gate (`changelog`, `description`, `english`, `Regression`, `branch-fresh`) is now ONE job for branches and forks alike (the `(fork)` twins and Tracy CI's `fork pull request checks` are gone; a fork now runs the full Tracy CI without secrets). No job asks for `tracy-check` / `tracy-light` / `tracy-build` / `tracy-lane-*` any more: those pools in `TracyHQ/tracy-runners` can be retired; keep `tracy-dev` / `tracy-staging` / `tracy-prod`. The vendored dsh submodule is fetched anonymously (`TRACY_VENDOR_DEPLOY_KEY` is no longer read), Node comes from `.node-version` via `actions/setup-node`, the pnpm store from the Actions cache (`.github/actions/node-pnpm`). `check-pr-merge.mjs` accepts a GitHub-hosted job (no lane label) and still refuses the production lane; `update-test-timings.mjs` takes shard timings from `ubuntu-*` runners. Before enabling the disabled image workflows: grant `TracyHQ/tracy` write access to the `ghcr.io/tracyhq/*` packages and watch the first build (`docs/references/public-repo-ci.md`, Cutover settings).
  **Why / Measured:** the repository is public, so hosted minutes are free and unmetered; the shared org quota that drove CI onto self-hosted runners on 08/09/2026 no longer applies. Runtimes before and after are in the pull request.
