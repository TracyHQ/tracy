- **A new site no longer lands on a bare upstream web image while its IMAGE_TAGS line exists, and a mover takes the ones that did onto the line for the same base** — David (Claude) · #201 · `fix/site-web-image-never-upstream` · 2026-10-29
  **Affects:** fleet hosts and whoever runs provision or the web images. `provision.sh` now builds a missing `IMAGE_TAGS` line on the spot (`web/build.sh --line <base>`, new single-line mode) instead of leaving the new site on `joomla:*`/`wordpress:*`; the first provision of a line on a host takes ~5 minutes longer, and a failed build leaves the site on the upstream base with a `!!` block in the provision log. Only provision builds: go-live, restore and snapshot resolve as before, and the strict callers (`render-compose.sh` by hand, `set-php.sh`, `enable-site-mail.sh`) still refuse, now naming `build.sh --line <base>`. `platform/joomla.sh` and `platform/wordpress.sh` resolve one base per road (clone 5-apache / php8.3-apache, fresh or quickstart 6-apache / apache). The tracy-host image now carries `vendor/joomla/joomlart-t4-skill` at `/opt/tracy-fleet/vendor/joomla/` so a Joomla line can be built from inside it: **rebuild and deploy the tracy-host image** to ship the fix. Sites already on an upstream image: `provision/move-off-upstream-image.sh --list` on each host, then `--label <label> --apply` one at a time (same base = same PHP; a base with no line stays and keeps the host-browser fallback).
  **Why / Measured:** the visual check draws inside the site's web container; the upstream image has no chromium or node, so 7 customer turns on prod1 answered `NO_BROWSER`, all Joomla. Reproduced on the local stand with an imported Joomla site on `joomla:5-apache` because `tracy/web-joomla:5-apache-20261027-r1` was not built there. `test/web-image-never-upstream.test.mjs` 23/23.
