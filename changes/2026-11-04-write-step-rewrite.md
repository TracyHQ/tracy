- **Write step bench, part 14: a rewrite writes only what differs from the last report** · Claude, for Akemi · #358 · `feat/write-step-rewrite` · 2026-11-04
  **Affects:** whoever runs the write step bench or reads its report. `runWriteStep` takes `last`, the report of the last run on the same site. Every stage compares by the line's `ordered` value (a picture by the sha256 in its path) and sends only what differs. Each report still holds all lines: one not sent keeps its status and value and gains `unchanged: true`, so the site check reads everything back, and `counts.unchanged` tells them from what this run wrote. Only lines the site took count as done: a failed line, a line the run did not reach and a line the site check read as different are sent again. A run that stops or is cancelled keeps what the site held for each line it did not reach. Bringing back anything an earlier run took off the site (an emptied slot or sentence, a dropped block or page, an unpublished menu item) stops with `NEEDS_NEW_SITE`, naming each, before the site is asked anything. `report.rewrite.left` names what the site still holds and the files no longer order; `timings.total` records the run's time. The report keeps the version `site-write-report/1`, and no door changes.
  **Why / Measured:** ADR 0044 decision 6. Unit tests only, on a fake site door; the time of a rewrite on dev is not measured yet.
