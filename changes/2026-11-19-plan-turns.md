- **A site planner run may write round 0 in turns of one conversation, the whole site first and then one page group a turn, merged and checked once** — David (WO pipeline) · #706 · `feat/wo-plan-turns` · 2026-11-19
  **Affects:** Rebuild and deploy tracy-web. Nothing changes until a planner bench run is started with `--plan-turns` (frozen as `harness.planTurns`, refused beside `--parallel-pages` above 1): the chain build does not pass it, and a run without it sends the same requests, byte for byte, as before. Such a run's round 0 records `reading.turnChecks`, the page-local plan check of each page group's turn, for measurement only. The shared bench loop (`lib/bench-run-round.js`) takes three more optional step hooks (`writesInTurns`, `turnsInOneConversation`, `checkTurn`), and `mergeTurns` also gets `{ row, ready }`; the writer's turns are unchanged.
  **Why / Measured:** Stage 1 of the proposed ADR 0045 (#703): copy and pictures can start per settled page group only once the plan is written per page group. Still to measure on dev before stage 2: plan time within 10% of a whole-answer run, no more standing failures, and how often the fix rounds touch a group that passed its own turn check.
