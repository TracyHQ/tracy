  **Affects:** Whoever wires site doors for a revision, a restore or an abandon: they now call the door client's `hide` and `unassign` (a client without them stops `door_not_available` before any door), and a restore or an abandon calls `deleteMedia` (dry run first) on the files the revision uploaded. `revision_needs_removal` is no longer a plan step stop: the write step stops with it, before any door, only for a place written in place that a revision no longer writes (its details name the door, `contract.removes` for a slot). `restore_needs_removal` remains only for a make whose id was never saved and for a slot taken out. The write step's value carries the flags `hidden_not_deleted`, `on_no_page_not_deleted` and `left_on_no_page`; a restore's `left` adds `hidden` and `kept` (files left, with why). The memory site models the three doors as measured (`write-order-memory-undo.mjs`).
