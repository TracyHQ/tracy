- **Readiness reader: read `REPLACE()` updates, skip `<code>` text and T3 default logos like the plugin does** — Akemi0x · `fix/readiness-reader-replace-update-code-text-t3-logo` · 2026-11-04
  **Affects:** the Road to live checks "Customize your site" (STAB-1, STAB-6). Anyone who shipped a quickstart whose `custom.sql` repairs demo data with `SET col = REPLACE(col, 'a', 'b') WHERE id = N`, whole-unit contracts over articles with `<code>` text, or a T3 template with an empty `logoimage` no longer gets a false red. No release, contract or plugin pin needs to change; /ops judges by the new reader once this is deployed.
  **Why / Measured:** `node scripts/template-customization-question-readiness.mjs <release> --tag quickstart/ja-diner/j6` on JA Diner j6 1.0.5 gave FAIL STAB-1 (16 slot samples off) and FAIL STAB-6 (2 locked rows off). Three causes: (A) `sql-dump.js` applied appended UPDATEs only as `col = 'literal'`, so the REPLACE() link repairs were skipped; (B) the text compare kept `<code>` text that capture and the plugin (`htmlSlots`, `unitPieces`, `writeUnit`) leave out; (C) a T3 style with empty `logoimage` renders the template default `images/logo.png`, which capture declares as the sample but the compare required an exact match with an empty value. After: STAB-6 PASS, STAB-1 not-checked with no dump problem (the plugin bytes are not read locally), 24 PASS and 0 FAIL. JA Boxing j6 output is identical before and after.
