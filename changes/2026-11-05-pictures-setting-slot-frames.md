- **Site pictures: a frame the kit writes through a setting slot (the T4 page background) goes in siteSettings, so its package is no longer refused** · Claude, for Akemi · #406 · `fix/pictures-setting-slot-frames` · 2026-11-05
  **Affects:** whoever runs the picture step (step 8) or the write step on a T4 kit with `site.body-background`. Since the kit made the background frame `writable: true` with `slotId`, step 8 listed it in `frames`; the export then reported "the kit has no image slot" for it and its twins, and the write step refused the whole picture package (`BAD_FILE`). Step 8 now chooses the list with one rule (`inputs-index.js` `listOf`): not writable, or tied to a slot of `site.settingSlots`, goes in `siteSettings`; its twins get no entry, the setting paints them. Picture packages made before this fix on such a kit must be made again.
  **Second fix, same PR:** `kitSlotIds` (`write-step/kit-slot-ids.js`) also reads the ids nested at `rowSlots[].slots[]`. Before, a write run whose copy filled such a slot (for example a class title slot of ja-boxing 1.0.11) stopped with `UNKNOWN_SLOT`. Test: `write-step-kit-slot-ids.test.mjs`.
  **Third change, same PR (ADR 0044, decision 26):** the write step no longer stops the whole run on one item. A look guard finding is written all the same and kept in `report.guard.findings` (and on the cell's line as `guard`); a slot the kit or the site does not have, a bad copy entry and a picture frame with no slot are left out with a `refused` line naming the owning step (`report.unaddressable`); everything else is written. The run still stops on a file that is not JSON or not its shape, another kit or contract, a file outside its folder or not matching its sha256, a site not ready, and a slot dispute. Step 11 gains two groups, `look-guard-findings` and `unaddressable-items`, which block on each item naming the cell and its step (copy 6, plan 3, pictures 8, brand 2, write 9). Reports written before this change leave both groups `unmeasured`.
