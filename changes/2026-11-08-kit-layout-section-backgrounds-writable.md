- **A picture a T4 layout paints behind the blocks is a writable kit frame that writes every layout slot holding it** — Joomla T4 batch 1 readiness · #625 · `feat/joomla-t4-batch-1-readiness` · 2026-11-08
  **Affects:** template preparers (kit `assemble` / `setting-slots`) and the picture step of a site build. A frame painted behind the blocks whose picture is a T4 layout section's `background_image` (an image slot of a `templateConfig-<id>` entity of the content map) now says `writable: true` and `writesTo` (every such slot showing that picture, across layouts), its twins included; it no longer counts as `kit-setting-slot-missing`. The picture step reads `writesTo` for the slot minimum width and the mapping export places the file in every listed slot. Layout hide/painted/backdrop exports are refused: the existing downstream stages do not address every layout slot. Frames without `writesTo` are unchanged. Rebuild the kit of a template with such frames.
  **Why / Measured:** JA Symphony 1.0.6 (5 frames), JA Impact 1.0.6 (3) and JA Vega 1.0.10 (4) read `kit-setting-slot-missing` because the kit only knew the page background setting (`body_bg_img`), while the content map already holds the layout section pictures. Tests: `template-kit-background-slot.test.mjs` fails without the link (5 pass, 1 fail) and passes with it (6/0), template-kit 332/332; `site-pictures-layout-background.test.mjs` + `template-kit-flow-reads.test.mjs` fail on the old code (14 pass, 4 fail) and pass now; picture and flow-read suites 187 pass, 0 fail.

  **Current behavior:** Picture alts are preserved. Layout hide/painted paths are explicitly refused until the write stages can address every bound slot. The focused export tests cover these refusals and ordinary placement; live layout writes have not been verified.
