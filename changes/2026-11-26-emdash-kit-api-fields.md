- **An EmDash template kit's blocks take their fields from the theme's stamps (the content API), every stored repeater becomes a list of its own rows, and each section is found again on the page the kit captures** — David (WO) · #761 · `fix/emdash-kit-api-fields` · 2026-11-26
  **Affects:** the template kit tool (`packages/cms/tracy-quickstart-tools/template-kit`) on EmDash only, and the people who cut EmDash kits. The committed JA Diner 0.1.4 kit stays wrong until it is cut again on a running site with `build --reread-sections`; Restaurant and Fresco print the same row-indexed stamps and page owner element, so their kits are likely wrong the same way (not measured), and Essence prints no row-indexed stamps (only the selector part can apply). A work folder's `emdash-sections.json` from before this change is read again on its own by `build` with a site, and named stale by a run without a browser. The planner, the site writer and the write step's closing ladder see more slots and lists in a re-cut kit: new `lists[].min` errors are honest gaps, not regressions. Joomla and WordPress kits do not change.
  - A stamp on one repeater cell (`items[0].title`, the form the themes print) places every row of that field in its block. Before, the stamp was cut to `items[0]`, which no slot is keyed by, so no repeater row of any EmDash template reached a block.
  - A section's selector counts the siblings of its own tag (`:nth-of-type`). Only the stamped read prints the page owner `<template>` as the first child of `<main>`, so the old `:nth-child` selector found the next section on the captured pages: on JA Diner's home the intro block was captured on the gallery, the gallery block on the menu tabs, and two blocks on the chef section ("the block was never shown").
  - Every field a block's stamps place is listed in the block (a block slot, a frame, or a list row), shown at the read width or not, so a closed tab's dishes and a hidden slide are declared. Each stored repeater is a list with `rowsFrom: "repeater"` and the repeater's rows, bounded by the map's group of the same name, else by the stored rows; a map group whose every slot is in those rows adds no list.
  - Words a block shows that equal another block's stamped field (a footer's "Location." beside a section's "Location.") are never its own field, and a stamped slot stays with its block when two blocks list it.
  **Why:** the JA Diner 0.1.4 kit listed 213 of the content map's 525 fields (`coverage.fields.notListed` 312), had no list at all, and put fields in the wrong blocks; EmDash Diner builds kept demo words in those slots (`arabian-tea-em4`, 26/11: empty-controls 12, plan-links 11, read-back 9, written-not-printed 4). Measured on the Diner map with home sections shaped as its views stamp them: 146 of the home page's 151 fields listed; the 5 left are fields no element stamps (button addresses, a carousel's label).
