- **An imported site's copy is asked on both its Joomla doors, and only a copy still starting reads "warming up"** — David (Claude) · #70 · `fix/reimport-copy-1b` · 2026-10-28
  **Affects:** the Apply door for imported sites (`apps/tracy-web` `sites/route.js` `pairFleetCopy`, `sites/component-target.js` `verifyCopy`, `copyDoorsFor`), its `COMPONENT_NOT_ON_FLEET_COPY` refusal (`copyReason` gains `redirected`, `no_copy`, `copy_error`, `not_engine`, none transient; a Joomla guest's JSON 403 is `not_engine`, no longer `unauthorized`), and the site agent's words for it (`tracy-site-tools` `site.mjs` `fleetCopyNext`). Live once `tracy-web` and the `tracy-dsh` image are deployed. A Joomla copy whose registered door (the one that answered the live site at import) does not reach the plugin is asked on its other door (front ↔ administrator), and the door that answers is kept.
  **Why / Measured:** beta report 28/10/2026, 1b: a re-imported Joomla copy refused every write for a day as "warming up". Simulated with a real server and node's fetch: a redirect, a missing container (`ENOTFOUND`) and a PHP fatal all read `unreachable` (transient) before; a front end gated at re-import left only the administrator door registered.
