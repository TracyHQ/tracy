- **The webhook Tracy wires on the releases repository now asks GitHub for `release` events, the only event `/github/release` reads** — readiness tooling · `fix/readiness-fu-dscheck` · 2026-11-09
  **Affects:** the Customize your site and Design system checks on /ops, and anyone publishing a quickstart release. A published or edited release now reads the releases and kicks both checks within seconds instead of at the next ten-minute read. The hook is repaired (PATCHed) by the first releases read after the deploy, on each deployment. Replacing an asset on an existing release (for example a new `tracy_setting.json` that pins a new version) still sends GitHub no event: press Refresh on /ops/cms quickstarts after such an upload, and both checks start for the new version.
  **Why / Measured:** the hook on the releases repository was created by `ensureRepoWebhook` with `push` only, while the door behind it ignores everything but `release`; its deliveries list only push events, each answered `ignored`. New test in `apps/tracy-web/test/github.test.mjs` fails on the old code ("the hook sends push, none of which the release door reads") and passes now.
