- **A revision shows again a record an earlier revision hid; a restore never writes a taken out key over an owner's value; a media delete follows the measured door.** -- AI quickstart work for #577 (#599 review fixes) | PR pending | `feat/ai-quickstart-575` | 2026-11-15
  **Affects:** Whoever reads a revision's write report or a restore's `left`. An operation a revision adds back whose record an earlier revision hid (or put on no page) is written again in place, same id, through `content.update` (`state: 1` / `published: 1`), after an owner edit check; the report flags `shown_again`, the run record keeps `state.hidden`, and the restore or abandon of that revision takes the record off again. A restore or an abandon stops (`restore_site_changed` / `site_changed_outside`, nothing written) when the owner set a JSON key the revision took out, or a column it emptied; every place is checked before the first write. A column a revision empties is in `state.cleared` and no longer in `state.wrote`. A JSON object Tracy no longer sends keeps the owner's keys inside it; an owner key inside a row of a JSON list stops `site_changed_outside`. A resumed attempt that stops before any write clears the mark an earlier attempt of the same run left. `read_back_mismatch` shows a status column's values instead of lengths. `media.delete` is read in its measured shape (`usedIn` rows `{type, id, title}` with a plural type); a missing file answers `write_failed`, so whether a file is there is read through `media`, never inferred from an error; a dry run is never answered from the door client's journal; the memory site answers as measured.
