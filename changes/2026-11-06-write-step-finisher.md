- **The write step bench can start at the finisher on a written site: `finish` finds raw markup printed on a page, repairs it through the write door, and keeps or undoes each repair** · Akemi (with Claude Code) · #426 · `feat/write-step-finisher` · 2026-11-06
  **Affects:** whoever runs `write-step-bench.mjs` or sets models in /ops > Model & AI. New command `finish --run <runId> --account <email> --out <dir> [--check-file <path>] [--site-pictures-file <path>]` on a run that `check` measured: it shoots every page the written site keeps (the write report's kept pages at their addresses now, the same list the site check opens; never a kit page the site dropped) through the host's capture door (1440 and 390 px tiles), asks the finder for faults, the fixer for a repair order, writes a valid order with its own `finisher-` apply id, re-shoots the page, and asks the checker on before and after crops of the repaired block at both widths (cut by the box of the element that prints the slot's words, which the host now sends when a capture asks `boxes: true`; the whole tile when no box holds them, and the log says which); a repair that is not better is reverted by its apply id. An order must target the slot the finder named, or, when it named none, a slot of that page holding the markup it reported; an order that would write the words the slot holds already is dropped as a no-op. It then runs the site check a final time with the first check's options (every group when the first ran every group; kept on the run), prints whether it gained a blocking failure the first check did not have in the groups both checks measured and names the groups it could not compare, and writes `repair-log.json` (with each repair's causing step and check), the crops, the finder's page tiles (`shots/`) and every model call's raw reply with the image files it was shown (`replies/`) into `--out`. Only the fault kind `raw-markup` and the order `fix-text` (the slot's own words without the markup) exist so far. Three new model doors, `finisherFinder`, `finisherFixer` and `finisherChecker` (migration 203), meant for `deepseek-flash` at max effort; a finder or checker model that cannot read pictures refuses the run. The picture looker, picture drawer and finisher doors now share one refusal ladder (`lib/door-ladder.js`), with unchanged codes and words for the picture doors. Also: `create-site` gets the site check's baseline functions from the command line, so `write-step/` no longer imports `site-check/`.
