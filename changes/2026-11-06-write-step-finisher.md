- **The write step bench can start at the finisher on a written site: `finish` finds raw markup printed on a page, repairs it through the write door, and keeps or undoes each repair** — Akemi (with Claude Code) · #426 · `feat/write-step-finisher` · 2026-11-06
  **Affects:** whoever runs `write-step-bench.mjs` or sets models in /ops > Model & AI. New command `finish --run <runId> --account <email> --out <dir> [--check-file <path>]` on a run that `check` measured: it shoots every kit page through the host's capture door (1440 and 390 px tiles), asks the finder for faults, the fixer for a repair order, writes a valid order with its own `finisher-` apply id, re-shoots the page, and asks the checker; a repair that is not better is reverted by its apply id. It then runs the site check a final time (kept on the run) and writes `repair-log.json` and before and after crops into `--out`. Only the fault kind `raw-markup` and the order `fix-text` (the slot's own words without the markup) exist so far. Three new model doors, `finisherFinder`, `finisherFixer` and `finisherChecker` (migration 203), meant for `deepseek-flash` at max effort; a finder or checker model that cannot read pictures refuses the run. Also: `create-site` gets the site check's baseline functions from the command line, so `write-step/` no longer imports `site-check/`.
