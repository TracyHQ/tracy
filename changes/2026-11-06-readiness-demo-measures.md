- **The template readiness verdict reads the site check's layout measures taken on the untouched demo (`demo-measures.json` beside the contract) and holds a new Joomla release on a template layout fault** — Template readiness · #436 · `feat/joomla-template-readiness` · 2026-11-06
  **Affects:** whoever prepares a Joomla quickstart: run `node apps/tracy-web/scripts/demo-measures.mjs --contract <contract folder> --base <demo address>` (or `--site <site key>` where tracy-web runs) on the untouched demo and commit the file it writes. It runs the site check's own `main-heading`, `empty-frames`, `text-overflow`, `orphan-row` and `blank-footer-column` groups (`src/site-check/demo-measures.js`) at 1440 and 390 through tracy-host's browser reader. The check (`src/lib/template-readiness/demo-measures-check.js`, piece `template-kit`, step `demo-measures`) answers `demo-measure-missing`, `-invalid`, `-stale`, `-incomplete`, one code per fault family (`demo-main-heading`, `demo-empty-block`, `demo-overflow`, `demo-orphan-row`, `demo-blank-footer-column`) or `demo-measures-clean`; a release already shown on Design inspiration only warns. `check-design-templates` leaves the file out of `contractFiles`, like `content-coverage.json`. **The site check of every built site gains two blocking groups (step 3, the plan):** `orphan-row`, a grid or wrapping flex row of three or more cards of one shape and about one width (each at least 120 x 80, outside menus and carousels) whose last row holds fewer cards than the full rows, starts at the first row's left edge and leaves at least half a card empty on its right; and `blank-footer-column`, a column of a side-by-side row in the site footer, at least 100 px wide, that holds markup but prints no words, link, picture, icon or control while a sibling column prints something. tracy-host reads both in its page measures (`orphanRows`, `blankFooterColumns`); a host from before them leaves the two groups unmeasured, not green.
  **Why / Measured:** JA Boxing 1.0.11, measured on its untouched dev demo (50 kit pages, 1440 and 390): no text overflow, four pages with no main heading (warnings), and no empty frame. A first measurement found 12 empty frames on the icon boxes (`div.img-icon`, `div.intro-image`): the template paints each icon with masked `::before` / `::after` over an img it keeps at opacity 0, which the host's empty frame measure did not count as a picture. That was a measure fault, fixed in tracy-host (`demo-qa-browser.js`): a picture painted by a pseudo element (mask with a colour, background image, icon font glyph) or by the element's own mask now fills a frame when it covers at least a quarter of it, as an inline SVG does; a bare colour block or a small placeholder glyph still leaves the frame empty. The same fix stops the false empty frames on every site built from JA Boxing.
