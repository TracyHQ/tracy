- **Write step bench, part 6: a review page for a write run** · Claude, for Akemi · #357 · `feat/write-step-review` · 2026-11-04
  **Affects:** whoever reviews a write run. New `node scripts/write-step-review.mjs --report <site-write-report.json> --package <picture package folder> --out <review.html>` (options: `--check`, `--site`, `--routes`, `--labels`, `--playwright`, `--no-capture`) builds one self-contained HTML page on the operator's machine, outside the repo. It reads the run's report (with `site-check/1` read back), the plan, the copy and `site-pictures/1`, takes headless captures of each kept page at 1440 and 390 (reading the site only), and shows one row per kept page, failed slots first. A Pictures tab shows each frame cropped from the real page (found by the sha256 in its file name) beside the nearby copy, the plan's description and the source picture, with Approve, Reject, a note, and buttons that copy the frames to redo (a JSON array of frame ids) and the notes. Choices are kept in the browser's local storage. Visible words are English defaults in `src/write-step/review-page/labels.js`; an operator who reads another language passes a JSON file of overrides from outside the repo with `--labels`. No server, database or customer-facing change.
  **Why / Measured:** the owner needs to see a write run on the site before it goes further. Unit tests on invented data, plus one test that drives a real browser when `PLAYWRIGHT_DIR` names a Playwright folder. A sample page was built from a real run outside the repo and checked in light, dark and at 390 wide with no horizontal scroll. A frame whose picture was refused is not on the site, so it has no crop.
