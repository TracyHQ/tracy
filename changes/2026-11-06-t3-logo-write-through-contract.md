- **The write step writes a T3 template's logo through its template style frame in the contract call, and the Template kit gate judges a logo spot with the same decision** — Write step · `fix/t3-logo-write-through-contract` · 2026-11-06
  **Affects:** the brand stage of the write step (`apps/tracy-web/src/write-step/brand-write-orders.js`) and the `kit-logo-unsettable` gate of /ops (`apps/tracy-web/src/lib/template-kit/flow-reads.js`), both now through `src/lib/template-kit/logo-write-path.js`. A logo spot goes through `template.siteSettings` only when its setting is a T4 site profile logo key (`site_logo`, `site_logo_dark`, `site_logo_2` and the small keys); any other spot (a T3 style param such as `logoimage`) is written through its content map frame (`templateStyle-N.M`) in the one contract call, or is unsettable. T4 kits produce the same orders as before. A kit whose logo spot names a setting the profile cannot write and no frame the content map holds now holds Publish instead of passing.
  **Why / Measured:** On JA Diner j6 1.0.5 (T3) the kit's header logo names `logoimage` and the frame `templateStyle-9.0`; the write step sent it to the T4 site profile, which a T3 site does not have, so the delivered site kept the demo logo while the gate showed green. The T3 favicon `.ico` is still not written (the kit leaves its setting empty for T3 and the writer only knows T4 profiles); that is a separate change.
