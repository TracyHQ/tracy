  **Affects:** The write step (#597) and the step chain wiring. ADR 0040's `keep` for `editorial.item_icon` still holds for builds from a human quickstart; it no longer applies to a build from an AI quickstart (owner decision 13/11). `picturesStep` now takes the page writer's output (`copy`), the icon library (`iconLibrary: {set, icons}`, the picture step's Phosphor catalog) and the build model's text call (`model`, else `vision`), and returns `icons`, `iconCounts` and `iconPrompt`. `selectIcons` (`icon-selection.mjs`) reads each item's written heading and text, code filters the library to candidates, one call of the standard build model ranks them (draft prompt `icon-ranking-prompt.md`, approval in #600), and a name outside the candidates, no model, an unreadable reply or an item left out throws `IconSelectionError` (`icon_name_outside_candidates`, `icon_ranker_missing`, `icon_ranking_failed`), so the step is re-run once and the build then stops and reports. Each icon carries a light and a dark version in colour roles at the frame the block store declares. A social icon is the mark of its link's network, never ranked. No match, an undeclared block level icon or a missing link hides the field with a reason. The step chain still runs the copy and pictures steps side by side: the pictures step must be given the copy step's output before this runs in a build. Nothing at runtime calls the step yet: no image rebuild needed.
