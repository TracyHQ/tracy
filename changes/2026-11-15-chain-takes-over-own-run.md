- **A chain build started again after a restart takes over the brand, plan, copy or pictures run it already queued, instead of waiting for it to end and doing the same work again** — David (WO pipeline) · #633 · `perf/wo-picture-look-ahead` · 2026-11-15
  **Affects:** Rebuild and deploy tracy-web. When a restart (a deploy) loses a chain build before the write, #574 starts it again; each bench step it reaches is refused while the lost attempt's run is still going (one run at a time per bench). The step now takes that run over when it is the build's own: started by the chain (`cli:step-chain`), the same research revision and kit, and for copy and pictures the same plan. Any other active run is waited for as before. Each bench still runs one run at a time across all builds.
  **Why / Measured:** Local stand, Central Padel run11 (15/11/2026): the web restarted 1 minute into the plan step; the resumed chain waited 18.7 minutes for the old planner run (which ended with 1 plan check failure), then planned again for 12.7 minutes and used that plan (13 failures). Tests `step-chain-own-run.test.mjs` 3 pass; every step-chain test file 142 pass, 0 fail. Case REG-PR-633-chain-own-run.
