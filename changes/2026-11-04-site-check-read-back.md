- **Write step bench, part 8: a bench-only site check reads a written site back against its write report** · Claude, for Akemi · #359 · `feat/write-step-bench` · 2026-11-04
  **Affects:** whoever runs the benches on dev. New command `check --run <run> --account <email> [--out <dir>]` in `scripts/write-step-bench.mjs`, running in the command's own process, and a new folder `apps/tracy-web/src/site-check/` whose entry point runs named groups and returns `site-check/1`. The first group is read-back: each failure names the page, slot, measured value and causing step, and a red read-back stops later groups. It uses no model and writes nothing to the site; the result is kept on the run's report. The write report gains `ordered` on written and refused lines, so reports from earlier runs come back unmeasured until the write step runs again. No table changed. No customer-facing change.
  **Why / Measured:** nothing compared a written site with what was ordered, so a failed write could pass for a content fault. Values are compared in the forms the plugin stores them: collapsed spaces on text, the picture's file under Joomla's media suffix, decoded references on attributes and percent encoding on links. Tested against a fake site door only; the first real run on dev is still to come.
