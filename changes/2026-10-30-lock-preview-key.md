- **The agent turns of a brief build read the real site while it is on its rebuilding page, with a preview key.** — build maintainers · #189 · `feat/brief-build-own-site` · 2026-10-30
  **Affects:** brief builds on Joomla and the `tracy_site` page reads. When the plugin lists "preview-key" in `info.site_offline.bypass_also`, the lock sends a fresh random key (`offline_preview_key`, only with `offline: 1`) and keeps it in the brief row's lock state only; it is replaced before the plugin's 6 hour expiry and dies at unlock, and receipts never carry it. A new door, `GET /api/sites/:key/preview-key` (conversation site, seat holder, no API key, no-store), answers it; `tracy-site-tools` asks it at the start of each `tracy_site` call (kept 20 s per site) and adds `X-Tracy-Preview-Key` to the container's curl of the site's own loopback reads only. Without the capability the lock is as before. The container browser reads (`page.look`, the visual check) send it to the site's own origin only, never to font or CDN hosts; a read that gets the offline page (503) after a renewal drops the kept key and retries once with a fresh one. Rebuild the web and dsh images.
