- **The GitHub API stub used by the publisher tests no longer times out idle keep-alive sockets, so a request sent while the test process is busy is answered instead of reset** — Akemi · `fix/wo-export-public-flake` · 2026-10-28
  **Affects:** tests only (`packages/fleet/tracy-fleet-operation/test/github-api-stub.mjs`, used by `scripts/test/wo-export-public.test.mjs` and `sync-brands.test.mjs`). No product code changes. Nothing to rebuild or redeploy.
  **Why / Measured:** CI failed now and then with `POST /pulls: network error reaching http://127.0.0.1:<port> (fetch failed)`. The stub runs on the test process event loop, which other concurrent cases block with synchronous git. With Node's default keep-alive timeout (5 s plus a 1 s buffer), the idle timer of a reused socket fired before that loop read the request already sent on it, and the socket was destroyed (ECONNRESET). A stress run of the "conflict twice" case with a 5 s slower export and a busy test loop failed 6 of 15 before the change and 0 of 31 after. The new `github-api-stub.test.mjs` reproduces it deterministically: red 3 of 3 on the old stub, green 3 of 3 on the new one.
