- **The write step hides a template's play buttons whose video address is empty, with one CSS rule the kit names, and the site check blocks on any shown one** — Write step · #TBD · `fix/hide-empty-video-play-buttons` · 2026-11-06
  **Affects:** template kits gain `site.emptyVideoButtons` (`template-kit/cli.mjs video-buttons --kit <file> --selector '<css>' --why '<where>'`, or `--none`); the JA Boxing 1.0.11 kit names `.video-btn[data-src$="/embed/"]`. Packagers of a template that prints a play button from a video field with no check that it is set add theirs when packaging. The write step writes the rule between `tracy-video-buttons` markers in the kit's head injection block after the contract call (`write-step/video-buttons-stage.js`); the look guard allows exactly that rule (`empty-video-buttons` exception). tracy-host answers `videoButtons` in its page measures, and a new site check group `empty-video-buttons` (block, step 9 when the kit names a rule, step 0 otherwise) reads it: a host image built before this change leaves the group unmeasured until it is rebuilt. ADR 0044 decision 27 is the one exception to decision 2 (hidden means removed, never CSS).
  **Why / Measured:** on a bench site with the JA Boxing 1.0.11 kit the four class pages showed 16 play buttons over the new session pictures, each opening `https://www.youtube.com/embed/?autoplay=1` with no video id, because `classes.php` prints `a.video-btn` whatever `exer_video_id` holds. In a headless Chromium on an invented page the rule hides the empty buttons and keeps the one with a video (`apps/tracy-host/test/demo-qa-reach-measures-browser.test.mjs`).
