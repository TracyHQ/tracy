- **`mint-agent-token.sh` answers the token custody of a compose file the same under GNU awk, mawk and busybox awk** — hano-xbt (Claude) · `fix-mint-token-gawk` · 2026-10-30
  **Affects:** any machine whose `awk` is GNU awk 5.2.1. It was found on GitHub's `ubuntu-latest` runner, where Tracy CI now runs: a short or truncated compose made `token_mount_custody` abort (exit 2, no answer) instead of answering `unknown`, so the mint, `emdash/upgrade-tools-image.sh` and `enable-site-mail.sh` refused it with an empty classification. No deployed host is known to run it under gawk: the `tracy-host` image installs none. They still refuse exactly the same files, now as `unknown`. Reaches a host only with the next image/script deploy. The door's agreement test (`apps/tracy-host/test/webroot.test.mjs`) now asks the whole custody table of every awk the machine has (gawk, mawk, busybox awk) besides the plain `awk`.
  **Why / Measured:** gawk 5.2.1 aborts with `fatal: internal error ... Node_array_ref` / `Node_illegal` when an array element that does not exist is passed to a function, then compared, then passed again (`function f(s){return s} END{f(L[9]); if (L[9]=="") q=1; f(L[9])}`); the matcher read `L[p]` past the last line. Lines are now read through `at(i)`, which never touches an element past `n`. Before: the table failed under gawk on `short form, relative to the site directory`; after: `node --test apps/tracy-host/test/webroot.test.mjs` 877/877, and the fleet-operation mint, render-compose and upgrade-tools suites 146/146 under each of gawk, mawk and busybox awk.
