- **The template kit tool captures, checks and packs a kit for an EmDash theme** — template kit tooling (agent) · `feat/emdash-template-kit` · 2026-11-10
  **Affects:** whoever prepares an EmDash theme for Road to live (first: `tracy-emdash-theme-restaurant` 1.0.2), and anyone who runs `packages/cms/tracy-quickstart-tools/template-kit/cli.mjs` or `site-cli.mjs`. New: an EmDash adapter (`lib/site/adapters/emdash.mjs`, `emdash-map.mjs`), `lib/contract-manifest.mjs` (an EmDash `contracts/<version>/` has no `manifest.json`, so the tool makes one from `content-map.json`; a `manifest.json` still wins, so Joomla and WordPress runs read what they read before), plain page addresses, and `--token-file` / `--reread-sections` / `--release-tag` flags. `apps/tracy-web/scripts/template-kit-step.mjs` prints what the Template kit step would answer for a kit that is not committed. Nothing in the Road to live code or in a released contract changes, and no kit is committed: Restaurant still reads `kit-missing` until its 1.0.2 kit is captured, eye reviewed and approved by a person. The commands are in the tool's README ("Make a kit for an EmDash theme"). Test: `test/template-kit-emdash.test.mjs`.
  **Also:** `logoWritePath` knows where an EmDash theme keeps its brand pictures (`settings.logo`, the chrome entry's `logo_dark` field, `settings.favicon`), so the Template kit gate no longer reads `kit-logo-unsettable` for them and the brand step accepts such a kit; `brand-write-orders.js` exports them as `via: "emdash-setting"` orders. The write step has no writer for that order yet, so nothing is written to an EmDash site until one is added (`write-step/brand-writes.js`).
  **Write step and kit:** the brand stage has an EmDash writer (`write-step/brand-writes.js`, `emdash-brand-door.js`): `settings.logo` and `settings.favicon` through one `emdash.settings` call, the dark logo through `emdash.entryField` (field made when missing, published languages only), each read back through the same action. The two actions are not served by the Apply door or the host yet (tracy-web holds only a read-only token); `scripts/emdash-brand-proof.mjs` runs them against a local site. The kit no longer drops the slot of a heading that has the same words as a button (`lib/kit-blocks.mjs`) and measures such twins on separate elements (`lib/read-text-fit.js`); Joomla and WordPress kit tests are unchanged.

  **Content map and kit checks (JA Restaurant 1.0.2):** the EmDash content map keeps link marks of Portable Text fields as anchors in a field's sample and reads declared limits from a theme's `seed/slot-limits.json` (each with its measurement, refused below the demo text); the kit names a rich text slot as the label of a phone link whose digits end the `tel:` address, also when the block's own entity is only its layout name.
  **Non-visual slots:** a theme may declare a text slot `nonVisual` in `seed/slot-limits.json` (an `aria-label`, the document title) instead of a number; the EmDash content map carries `nonVisual` and `nonVisualFrom`, the kit lists the slot with no `maxCharacters` and the reason, and the coverage gate asks no limit of it.
