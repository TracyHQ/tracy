- **The 9b repairs of a step chain build fold into its one Tracy setup row** — Akemi Nguyen · #477 · `feat/9b-setup-row` · 2026-11-08
  **Affects:** chain builds only (`workflow: 'step-chain/1'`); every other build and the write step bench behave as before. The repair pass opens one dsh session per page; each is now written to the new `setup_session` table (migration 206) before any prompt reaches it, and the Apply door records a write made in such a session as `origin = 'setup'` under the build's run id. Site changes (V2) keeps those sessions' turns out of the list and groups their writes with the run's own, so a build shows one "Tracy setup" row holding the Write step writes and the 9b repairs. When the pass ends (also when it was taken back because the Site check could not run) each repair session is archived through `workspace/archiveSession`, so it is not listed in the customer's chat sessions; if dsh refuses, it is logged and the session stays listed. Files a repair turn committed ride on the same row (their counts add to the run's, the newest commit is shown), never a row of their own. An archive that fails is logged with its reason and never breaks the pass. The old V1 list (`/activity` without `version=2`) is unchanged: no first-party surface reads it.
