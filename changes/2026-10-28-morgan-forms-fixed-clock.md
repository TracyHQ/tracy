- **The wp-ja-morgan and wp-ja-restaurant form-limiter tests run on a clock the test sets, so a ten-minute mark between two requests no longer turns them red, and they now pin the limits exactly** — CI maintainer (Claude) · #85 · `fix/morgan-forms-rate-flake` · 2026-10-28
  **Affects:** whoever runs or edits `packages/cms/tracy-wordpress-theme/test/wp-ja-morgan-forms.test.mjs` or `wp-ja-restaurant-forms.test.mjs`. Test only: the themes' `inc/groups/account.php` is unchanged. The probe now loads `account.php` inside a namespace whose `time()` answers the `now` each request is given, so a case that needs a different moment passes it to `request(base, n, spec, now)` instead of relying on the wall clock.
  **Why / Measured:** CI run 40716937675 (tests 2/2) failed "overlays: one client cannot mail more than five addresses per window" with `[0, 1]` for `[0, 0]`. The limiters count places in fixed windows of `intdiv(time(), $window)`, and request 9 differs from request 8 only in what `time()` returns, so a 600 s boundary between them hands the client fresh places. The 15:40:17 log stamp is when the reporter flushed buffered lines (overlays and src printed 0.3 ms apart for ~800 ms cases), not when the case ran. Reproduced under real PHP with libfaketime moving PHP's clock across 15:40:00 before request 9. The cases now also fail for a client limit of 4 or 6, a registration limit of 4 or 6, a window index that never changes, and a theme that reads `\time()` past the test's clock.
