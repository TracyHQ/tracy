- **Every Joomla and WordPress site's Apache replaces a child after 100 connections (`MaxConnectionsPerChild 100`, was 0)** — Fleet maintainers · #TBD · `site-apache-recycle` · 2026-11-16
  **Affects:** fleet hosts and whoever builds or rolls the site images. New tags `20261116-r1` on every `web/IMAGE_TAGS` line carry `web/tracy-prefork.conf` in `conf-enabled`; other prefork values stay the image defaults, and a demo's `zz-tracy-demo-limits.conf` (500) still loads last and wins. The updater only BUILDS the new tag (`web/build.sh` when `IMAGE_TAGS` changed); it does not move a running site. Per site, one at a time, on the host: `bash /opt/tracy-fleet/scripts/provision/set-web-image.sh --label <label> --image tracy/web-<platform>:<base>-20261116-r1` — the image is the `web/IMAGE_TAGS` line for the site's SAME base (same PHP; read the site's current tag in its `docker-compose.yml`). It rewrites only the web image line and force-recreates only the web container; add `--no-start` to stage it. It touches no mail token and needs no `HOST_SECRET`. A site still on a bare `joomla:*`/`wordpress:*` image goes through `move-off-upstream-image.sh --label <label> --apply` first. New sites get it at provision.
  **Why / Measured:** one site's web container held 550 MiB on a real host (16/11): 11 children alive 20 days, three ~180 MB RSS each, for 168 requests/24 h; with 0 a child is never replaced. 100 because a connection counts once however many keep-alive requests ride it, and a larger number is never reached on a quiet site. `test/web-prefork-recycle.test.mjs`.
