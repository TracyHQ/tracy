- **Sync from live: the live read's own timing reaches the sync row again, and the rows the live site added with a held record stay out of the copy and are named with it** — agent (Claude) · `fix/live-sync-read-timing-held-rows` · 2026-10-28
  **Affects:** the host image (`webroot-sync.sh`, `lib/live_sync.py`, `apps/tracy-host`) and `apps/tracy-web`; nothing to migrate. The read's timing line was printed as Python's spaced JSON (`{"ok": true, …}`) while tracy-host and tracy-web matched a compact prefix, so every row's `answer.timing.read` was null; the script now prints compact JSON, and both readers parse the line instead (older hosts still print the spaced form). When both sites added a record under one number in a table the adapter cannot renumber (`added-both`, held; "Sync anyway" keeps Tracy's), the rows the live site added for its record in the tables `dependents` declares no longer graft onto Tracy's record: they stay out and are listed on the held record as `belonging` (`belongingCount`), or in `skipped` (`belongs-to-held`) when a person already picked "ours". A table the copy left alone is still taken whole, and only the held record's live-added rows are removed from it afterwards. `dependents` now declares Phoca Cart's per-product tables (from Phoca Cart 6.1.9's install SQL); they count as rows of a record, not records. `phocacart_item_groups` has no key in Phoca Cart, so `naturalKeys` gives it its four columns. tracy-web passes `belonging` through `held`, `dropped` and `conflicts`; the dialog does not word it yet. WordPress: no `dependents` in its policy, and its core tables are renumbered, so nothing changes there.
