- **The content coverage file names each page that failed to render, a resource that never answers no longer fails a page, and JA Boxing 1.0.11 is measured again with no failed page** — Template readiness · `feat/joomla-template-readiness` · 2026-11-06
  **Affects:** `packages/cms/tracy-quickstart-tools/content-coverage/`: `content-coverage.json` keeps `pages.failed` (the count) and gains `pages.failures`, one entry per page that did not render (path and query only, never the stand address, with `mapPage`, `status` or `error` when known); readers that only use the count are unchanged. `renderPage` now treats a page as rendered once its document is loaded and waits at most 15 seconds more for the load event, so an avatar host or font CDN that a network blocks no longer turns a page into a failed page (it used to time out after 45 seconds). The JA Boxing 1.0.11 coverage file is replaced by a fresh measurement on a stand restored from the released quickstart; `content-map.json` is byte-identical.
  **Why / Measured:** The release-time file said `failed: 1` without naming the page. A re-measure on a clean stand failed the same author listing page twice: its avatar request to an external host was redirected by the measuring network to a block page that never answered, so the load event never came (the server answered in 0.1 seconds). With the fix: 61 pages, 0 failed, coverage 99.6 / 100 / 89.3, no blocking hole; the readiness command now reports the `contract` piece as done.
