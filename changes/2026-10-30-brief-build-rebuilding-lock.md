- **A brief build keeps the public site on a rebuilding page while it writes, and a failed fill shows as Failed with Retry.** — build maintainers · #189 · `feat/brief-build-own-site` · 2026-10-30
  **Affects:** brief builds and their detail panel. Before its first write, a brief build that the build runner will judge locks the site through a CMS-neutral step (`sites/site-lock.js`, kept on the brief row as `timings.siteLock`); the Joomla writer (`site-lock-joomla.js`) sets Site Offline through `site.identity` only when the plugin advertises `info.site_offline` with the bearer bypass, otherwise the run notes that the site stayed open and goes on as before. While locked, every read Tracy makes of the site (the engines' site reader, the final check's page reader, the site file reader, and the host's picture-overlap browser, which sends it to the site's own origin only) sends the site's component token as `Authorization: Bearer`, to the site's own origin only. The runner unlocks once the final check says clear or Needs fixes (or after the fill of a manual build) and keeps `receipt.siteLock`; any failure leaves the site locked. A failed fill is written as `receipt.fill` and the panel shows Failed with Retry instead of done with Hand off. The Add site popup's own Apply never locks. The cleanup agent turn still reads pages through an in-container curl without the token (the Joomla token is not mounted in the container). The frame readers (`empty-frames.js` and its two helpers) moved to `lib/`, with re-exports left in `sites/brief-engines/`. WordPress and EmDash have no lock writer yet. Needs the Claude Cowork for Joomla release carrying the offline lock; rebuild the web image before the next brief build.
