- **A brand run now loads the brief's found logo into its run folder before the first model call** — Claude, for Akemi · #321 · `feat/brand-bench-tools` · 2026-11-03
  **Affects:** the brand bench only. `brand.logo` is a media id; nothing used to put those bytes where `open_image`, `measure_logo` and `cut_mark` look, so the agent could not see the customer's logo. When the worker claims a run it reads the `wo_media` row, fetches the object through the same object store Website Opportunities uses (`placeMediaObjectsFor`, passed to `productionWiring` as `objects`), checks the sha256 and writes `media/<id>.<ext>` (png, jpg, webp or gif as stored, any other image as png), the place and name the approved lab used. A logo that is missing, not stored, unreadable or not an image fails the run with `BRAND_LOGO_UNAVAILABLE: <reason>` before any model call. `scripts/brand-bench.mjs run --brief-file <path> --logo-file <path>` uses a file on the server instead of the lookup; it is staged before the run is queued and refused when it is not an image or the brief names no logo. Where the logo came from is on the run as `logo_source` (`{kind: "media", mediaId}` or `{kind: "file", name}`, never bytes or a path): migration 197 adds that column.
  **Why / Measured:** the end-to-end symbol-logo test used to write the logo into the run folder by hand; it now gets it through `--logo-file` staging. New tests: `brand-logo-load` (fake pool and object store, nine failure and format cases) and `brand-bench-logo` (media path through the worker, missing media and missing store fail with zero model calls, `--logo-file` and its refusals). All `brand-*` tests and `module-graph` pass.
