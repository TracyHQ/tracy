- **The brand bench checks the brand on a real page: after the gate accepts (or after the safe version) it writes the brand on one trial site, captures header, footer, opened phone menu and tab icons in light and dark, and judges them** — Claude, for Akemi · #322 · `feat/brand-real-page` · 2026-11-03
  **Affects:** the brand bench only (`apps/tracy-web/src/brand-step/real-page/`), plus two small, backward-compatible host changes. `brand_run.real_page_verdict` (migration 196, column already there) now holds `{ verdict: pass | fail | stopped, checks, failed, writes, files, ... }`; the captures are in the run folder under `real-page/`, so `get` downloads them with `real-page/verdict.json`. A write or capture error gives `stopped` with `stage` and `reason`; the run still ends `succeeded` with its brand file. Without `TRACY_BRAND_TRIAL_SITE` (the trial site's label) and `TRACY_BRAND_TRIAL_ACCOUNT` (an internal account holding a seat on it) nothing is written and the bench runs as before.
  **Why / How:** the writer reuses `setSiteBrand` (logos, `.ico`, site name, footer logo through the template's footer slot), adds the T4 small-logo settings for the phone menu (CSS fallback only when the profile has none), puts PNG 32, PNG 512 and the phone icon 180 into the kit's head block (module named by `site.head.injection`), and writes the accent-only module through the host's `site-ds-slot` job. It refuses every site except the configured trial site (`trial-guard.js`). Capture and judge take any site (step 9 can call them on a customer's site): tracy-host gets a new capture mode `real-page/1` (`real-page-views.js`; the template-card capture is unchanged), the judge measures letter height and contrast from the pixels, checks the menu mark, the footer logo, every favicon size and that only accent-family colours differ from the template, and a model looks once through the brand reviewer door and can only add a failure. The host's `site-ds-slot` validator now also accepts a `brand:<bg>-<fg>-<accent>` system id.
