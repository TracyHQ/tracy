- **The demo baseline of a quickstart version is made at step 0 and kept beside its contract; the bench reuses it, and Publish of a new JA Boxing version waits for it** · Akemi (with Claude Code) · #428 · `feat/demo-baseline-in-template-kit` · 2026-11-06
  **Affects:** whoever packages a template kit, runs `write-step-bench.mjs` or `site-check-baseline.mjs`, or publishes a JA Boxing version on /ops. Step 0 now ends with `demo-baseline.json` beside the contract (next to `template-kit.json`): measure the untouched quickstart site with `apps/tracy-web/scripts/site-check-baseline.mjs` (only tracy-web reaches a site's host), then `template-kit/cli.mjs baseline --from <measured file> --contract <dir>` writes it, dropping the measuring time and refusing any value that names a machine. The bench and the site check read that file first; `WRITE_BENCH_BASELINE_DIR` is only a fallback cache for a version with no committed file. `create-site` settles the baseline on its untouched site: a stored one is reused and no page is measured, a missing one is measured once into the cache; it prints `baseline reused (stored)`, `baseline measured (none was stored)` or `baseline measured again (forced)`, and with neither a committed file nor a cache it measures nothing and says so. `create-site --force-baseline` and `site-check-baseline.mjs --force` measure again on purpose (about six minutes); a committed file still wins on the next read. `check` prints whether the baseline was reused or is missing. On /ops, the Template kit step of a template listed in `apps/tracy-web/src/lib/template-kit/demo-baseline-policy.json` (JA Boxing only) holds Publish with `kit-demo-baseline-missing` while the file of that version is missing, unreadable or of another version; an already published version only warns, and every other template is unchanged. JA Boxing 1.0.11 ships with its file. The production build path (`takeDueBaselines`) reads a different, per build baseline and is unchanged.
