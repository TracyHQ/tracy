- **The write step creates the pages a plan asks for, through the plugin door, before links are pointed at them; a rerun does not make them twice** · Claude, for Akemi · #375 · `feat/write-step-pages` · 2026-11-04
  **Affects:** the write step bench and the site check, and whoever builds the Joomla plugin (claude-cowork `feat/hide-ops`, `info.page_create`, no version bump yet). A new stage (`write-step/page-create-stage.js`, `page-create-lines.js`) runs before the link stage for every `site.legalPages[]` with `use: "create"`: a category `Site pages`, an article with the copy's title and body, and a menu item, each through `content.batch` and each with `tracy-page:<id>` in its `note`. The check stops with `PAGE_WITHOUT_COPY` when the copy has no words for such a page. An older plugin gets failed lines naming `info.page_create` and no row. `report.keptPages` gains the page, so the site check opens it. New report lines: `<id>:heading` and `<id>:address`.
  **Why / Measured:** `content.batch` already creates all three rows on a bound site with a replay by request id and an undo, so no new operation was added; the plugin only stops counting marked rows as inventory, so the contract reads no drift and its baseline stays byte for byte. The item is left out of printed menus (`menu_show: 0`) and the template's own row points at it, so a menu column keeps its length. Proved on invented data with the plugin's engine tests and a fake site door. Run offline on a frozen plan with a fake door: three batches on the first run, none on the rerun. Nothing on a real site is measured yet: whether the page answers at its address, whether the template prints its words well, and whether `menu_show: 0` holds for every menu renderer.
