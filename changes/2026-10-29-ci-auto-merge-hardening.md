- **Auto-merge into `develop` merges only team members' PRs that touch no CI-sensitive path, and its privileged jobs run GitHub-hosted.** — CI maintainer · #130 · `ci-auto-merge-hardening` · 2026-10-29
  **Affects:** anyone relying on auto-merge. A PR opened by a bot (Dependabot, a GitHub App agent) or by an author who is not `OWNER`/`MEMBER`/`COLLABORATOR` is no longer auto-merged (`author-not-human` / `author-not-team` / `author-missing`). Neither is a PR that changes, adds, deletes or renames a path in `.github/CODEOWNERS`, a script that a `run:` step of the five gate workflows calls (read at run time), or `.github/`, `scripts/ci/`, `scripts/lib/`, `scripts/check-*`, `turbo.json`, `scripts/auto-merge-develop.mjs` or `scripts/check-pr-merge.mjs` (`sensitive-files`), or one whose file list reaches 3000 files (`files-incomplete`). A person merges those. Test files, app code and `package.json` scripts stay trusted to team authors. `auto-merge-develop.yml` › `merge` and `ci-label-rerun.yml` › `rerun` now run on `ubuntu-latest`, so they use the org's GitHub-hosted minutes; nothing else moves off the self-hosted runners. The change takes effect only once the workflow file reaches `main`.
  **Why:** a `pull_request` run executes the PR head's workflow files, so a PR that rewrote them could turn its own gate green and be merged by the bot; and the merge token sat on persistent runners that also run PR code.
