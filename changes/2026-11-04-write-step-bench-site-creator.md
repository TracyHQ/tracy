- **Write step bench, part 1: a bench-only command creates a trial site from a template kit's quickstart and proves it answers the kit's contract** · Claude, for Akemi · #353 · `feat/write-step-bench` · 2026-11-04
  **Affects:** whoever runs the benches on dev. New command `node scripts/write-step-bench.mjs create-site --kit <contract id> --account <bench account>` (also `status`, `list`) in the tracy-web image; new table `write_bench_site` (migration 198) that records every trial site the command made. The command creates a site by the customer's door (`POST /api/sites`, 202 with a job id), waits for the job, reads `content.contract inspect` through the Apply door, refuses with both contract ids named when the answer differs from the kit's `contract`, prints the creation time, and then deletes the previous bench site. A failed run deletes its own failed site and keeps the reason on its record. The quickstart and the contract come from the kit it is given, so no template version is written in code. It deletes only sites named in its own table whose label has the bench shape, never a customer site, and nothing outside the bench command imports it. No customer-facing change. ADR 0044 (write step and site check) and its glossary terms are added.
  **Why / Measured:** the write step needs a fresh site per run that is created the way a customer's is; the Apply door only accepts a site that holds the contract of its template, which the kit names.
