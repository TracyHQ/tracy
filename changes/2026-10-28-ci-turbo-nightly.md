- **The `turbo-config` gate traces no test suite on a pull request (`--check --structure-only`); the full trace runs on the nightly and on manual runs** — Hano · #72 · `ci-turbo-nightly` · 2026-10-28
  **Affects:** every pull request's `build check (checks)` row, and whoever reads a red nightly. A pull request is still red for a broken task structure or a hashed file git ignores, but a suite that starts reading a path outside its task's Turbo inputs is now caught by the next nightly (19:30 UTC) or a manual Tracy CI run, not on the pull request. On a pull request into `develop` with Turbo data, a task that misses the cache still audits its own reads in its test row (`--task-part`), as before. A local `pnpm build:check` still runs the full `--check`. Pinned by `scripts/test/check-all-turbo-config-args.test.mjs`. The comments edited in `scripts/ci/turbo-setup.mjs` (a turbo.json `globalDependencies` file) and `scripts/ci/related-tests.mjs` (in every task's inputs) change every task hash, so the Turbo cache is invalidated once: this PR runs every Turbo task, and pull requests right after its merge may too until the cache is refilled.
  **Why / Measured:** two pull-request runs on 28/10/2026: `turbo-config` took 8.3 and 26.0 minutes of the `checks` row (`--changed-since HEAD^1`: 12 changed files touched the inputs of 26 of 51 tasks, all traced), while every other gate took seconds to 2 minutes. Locally, `GITHUB_EVENT_NAME=pull_request pnpm exec tsx scripts/check-all.ts --only turbo-config` now reports `51 tasks, 0 measured now` in 32 s.
