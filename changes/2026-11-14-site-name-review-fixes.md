  **Affects:** The build chat flow and the partial re-run. A site name answer, or a card edit of the business name, that names a held person (whole words, case folded) is refused with `site_name_invalid` before any model call; the problem text is neutral and never prints the person. A card edit of the name is held to the template's business name limit (`site_name_too_long`, worded with the limit) and to the answer's text checks (`site_name_invalid`); both are plan edit problems with those codes. `withheld` gains `heldNames`, the names research first held, which is never removed; `withheld.names` (what is hidden now) is derived from it on every answer and edit, so a held name shown by one edit is hidden again by the next that does not write it (old profiles without `heldNames` fall back to `names`). Zero width characters are stripped from a site name; bidirectional controls and other format characters are refused; tabs and no-break spaces collapse to one space; every problem on the site name question (a second answer, a choice, a skip) is `site_name_invalid` with `details.question`. Contract B refuses a `site-name` question whose free text cap is above 120. Plan edit refusals word the problem in a neutral sentence that names the thing by its plan label (never an internal id), with the technical text in `details.problems` (not for display). Nothing at runtime calls the edit gate yet: no image rebuild needed.
