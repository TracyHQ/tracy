- **A logo hint finds its picture's media row even when its url was re-signed, and a from-scratch research reads the logo again** — Akemi, with Claude · see the pull request that adds this file · `fix/logo-hint-matches-deduplicated-media` · 2026-11-09
  **Affects:** Website opportunities place research (`packages/wo/website-opportunities`). The media step now records on each logo hint (a website `logos[]` item, a social profile picture in `media[]`) the `mediaId` of the row its url became, and the brand stage matches hints by that id as well as by url. A brand stage that looks at zero candidates no longer replaces a found logo still in the snapshot by `none`. Places whose logo turned `none` this way get it back on their next Research again; the first run after the deploy may publish a new snapshot only because the hints now carry their `mediaId`.
  **Why / Measured:** on dev, a whole Research again on a place whose Instagram profile picture was stored on 26 Oct ended with `logoResearch.status: none`, zero candidates and no vision call. The CDN had signed a new url for the same bytes; the media step kept the older row (one row per sha256), so no stored row carried the new url, and `logoCandidatesOf` matched hints by url only.
