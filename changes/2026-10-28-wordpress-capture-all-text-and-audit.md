- **WordPress capture of all visible text, and the content coverage audit on WordPress** - Akemi (Claude) · #43, #41 follow-up · `feat/template-readiness-rules` · 2026-10-28
  **Affects:** whoever captures a WordPress contract, whoever publishes a WordPress template from /ops. `capture-contract.mjs` gains `--all-text` (a slot for every heading, paragraph, list item, button, table cell, cite and menu label, named or not, plus a url slot for each link in them; a block with no name is addressed by `blockType` and `occurrence`) and `--role-vocabulary 2|3`; the default capture is unchanged byte for byte. The audit now loads a WordPress contract (pages open as `?pagename=<slug>`, rows of `posts`/`options` are matched to entities by slug, only the theme is read as source). `policy.json` lists `wordpress` under `platforms`, so Road to live reads a WordPress `content-coverage.json` like a Joomla one: **a new WordPress release with no measurement now waits at `coverage-not-measured` instead of passing as not needed**, and a live one warns. Slot fit is still Joomla only. The panel gets guide text for `coverage-labels` and `coverage-live-labels` (other languages carry the English text for now), and the Content coverage prompt names the WordPress capture and contract folder.
  **Why / Measured:** a WordPress capture took only named plain-text blocks, so the audit had nothing to match and the label rules had nothing to judge (spec #37). Fixtures: `capture-all-text.test.mjs`, `content-coverage-wordpress.test.mjs`, the WordPress cases of `content-coverage*.test.mjs` and `problem-guides.test.mjs`. Not changed here: the plugin writer for a position target (such a slot has no `input`, so nothing writes to it), and template parts and custom HTML blocks are not captured.
