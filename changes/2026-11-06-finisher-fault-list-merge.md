- **The finisher works from the full closed fault list and merges the first site check's failures with the finder's faults, repairing a check failure only when the live site confirms it** · Akemi (with Claude Code) · #426 · `feat/finisher-423` · 2026-11-06
  **Affects:** whoever runs `write-step-bench.mjs finish` or reads `repair-log.json`. The finder now names every kind of the list (unreadable text, raw markup, empty frames, broken layout including heading words glued together at phone width, demo facts, links to a 404 or the demo, demo phone or e-mail links, demo or duplicated title or meta, wrong alt, lost template design) and may name any other visible fault as `other`, which is logged only. For lost design it is shown the template demo's shot of each block the page shows (the kit images, at 1440). A missing or repeated h1 is logged only. First site check failures of the listed kinds join the finder's faults; one named by both is repaired once (`sources` in the record). A visible failure the finder did not see, or an invisible one (link target, alt) the page served now no longer holds, is logged as `measurement-wrong`; a link failure with no slot, or an item the write step had nothing to write to, is logged as `no-door`. A finder fault whose kind a check group measured green names that group under `missedBy`. New flag `finish --check-now [--all-groups]` runs the first site check alongside the finder and writes `first-site-check.json`. The bench prints a `merge:` line. Theme switching (shooting the other theme) is not in this change.
