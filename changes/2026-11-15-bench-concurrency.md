- **Each model bench (site planner, site writer, picture step, brand step) holds up to 3 runs at once and plays them side by side, so chain builds started together no longer queue their steps** — David (WO pipeline) · #633 · `perf/wo-picture-look-ahead` · 2026-11-15
  **Affects:** Rebuild and deploy tracy-web; migration 218 drops the four one-active unique indexes (`site_planner_run_one_active`, `site_writer_run_one_active`, `site_picture_run_one_active`, `brand_run_one_active`) and adds partial `*_run_active` indexes. The limit is the constant `BENCH_RUNS_AT_ONCE` = 3 (`apps/tracy-web/src/lib/bench-sql.js`, one value for all four benches, no operator setting): a start counts the active runs and inserts under an advisory lock and refuses the 4th with the same `*_RUN_ACTIVE` code, now worded "At most 3 … runs at a time: …" and naming every active run (the refusal's `active` is the oldest, `activeRuns` all of them); `BENCH_QUEUE` and `BRAND_QUEUE` lease 3 runs at once, each with its own lease, heartbeat, cancel and resume. Anything matching the old "Only one run at a time" text should match the `_RUN_ACTIVE` code instead. A chain step now looks for its own build's active run before every start (not only after a refusal, which no longer comes while there is room) and never takes over one asked to stop. Provider load: up to 3 runs per bench call the model at once (12 across the four benches, and a picture run fans out further into looks and drawings), so three builds started together put three times the calls in flight at a provider. The DeepSeek balance before/after stored on a run is the account's, so it includes the runs that overlapped it.
  **Why / Measured:** Two WO builds started together ran their plan, copy, pictures and brand steps one after the other: each bench refused a second run and the chain step polled every 10 s until the other build's run ended. Tests: `bench-runs-at-once.test.mjs` 11 pass (the four starts admit 3 and refuse the 4th, starts from two pools admit exactly 3, two workers lease 3 and never one run twice, a cancel stops only its run, the picture looker keeps each run's state, the chain takes over only its own run); every bench and step-chain test file (152 files, throwaway Postgres): 1103 pass, 0 fail, 0 skipped.
