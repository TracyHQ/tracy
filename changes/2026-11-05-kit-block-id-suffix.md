- **Template kit: the id-suffix module rule only runs on T3 pages and skips template layout ids** — Claude, for Akemi · `fix/kit-block-id-suffix` · 2026-11-05
  **Affects:** whoever builds a template kit for a T4 template (JA Boxing 1.0.11 first). `find-blocks.js` found an assigned module with no wrapper by the one element whose id ends in `-<module id>`. On a T4 page that matched layout ids: the Main Menu (module 1) became `#t4-section-1`, the section around an unrelated block, so the kit gained a false `block-1` with wrong demo texts and nested pricing modules. The rule now runs only on a T3 page (`#t3-header`, `#t3-mainbody`, `.t3-wrapper` or `.t3-off-canvas`) and never accepts an id starting `t3-`, `t4-`, `col-`, `row-`, `item-`, `menu-item-` or `grid-`. T3 module chrome (`#mod-<N>`, `#block-<style>-<N>`, `#uber-<layout>-<N>`) is still found.
  **Why / Measured:** new tests in `template-kit-t3.test.mjs` failed before the fix (module 1 matched `#t4-section-1`; `#t3-section-7` matched module 7) and pass after; the T3, frames, blocks, assemble and row-pairs template-kit tests stay green.
