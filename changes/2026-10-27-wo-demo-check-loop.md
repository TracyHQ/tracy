- **Agent demo check: sweep rounds re-read only changed pages; template categories renamed on their archive or reported at once** — Hano · #24 · `fix/wo-demo-check-loop` · 2026-10-27
  **Affects:** anyone reading the agent demo's `tracy_demo check` or its sweep (`apps/tracy-web` `client-demo.js`, `residue-sweep.js`; `apps/tracy-host` `demo-qa-browser.js`, `demo-read-cache.js`). The check after a residue sweep round is now incremental like a check after a counted one (`checkIsIncremental`): the host reads again and the look shoots only the pages whose served document changed; a pass found that way is still confirmed by a full read before it counts, and so is a failure that would be counted (a kept read is the page as loaded, before lazy content scrolls in, so it is never the evidence for a counted failure). The host no longer keeps the read of a page a failing check or the residue ledger names, keeps a read only for a read asking the same (discovery, wordmark, logo, sentinel words), and drops the reads of a run that ended without its checks. A template category or tag rename is planned once on the term's own archive page (where the WordPress replace job reads the term), not once per post page that shows it; on Joomla and EmDash, a category link off the site, or a rename an earlier round of the same counted check already sent that still shows, it is reported unresolved on that check and not counted in the sweep's `left`. `qa.residueSweeps.renamed` keeps the names sent per counted check.
  **Why / Measured:** on the dev deployment one check call of a WordPress ja-diner demo ran about 60 minutes (six sweep rounds, each followed by a 5–7 minute whole-site read and look), ended pass:false with four template category names still shown, and the build hit DEMO_STEP_TIMEOUT.
