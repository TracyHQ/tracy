## キーとは、範囲を狭めたシートです

すべての API キーは **1 つのアカウントと 1 つのサイト** に属します。キーを作成する人はそのサイト上に有効なシートを
持っていなければならず、キーは **その人として** 動作します。すべての読み取りと書き込みは、その人の名前で認可され、
リースされ、監査されます。「自分のすべてのサイト」に届くキーは存在しません。1 つのサイトに 1 つのキーです。

キーができることは、次の 2 つの共通部分です。

1. **シートの実効的な権限** — サイトまたはワークスペースのポリシーがロール（`owner`、`admin`、`developer`、
   `editor`）に付与するツールセット。owner はすべてのツールセットを持ち、editor はデフォルトでは
   `content` のみを持ちます。
2. **キーのスコープ** — `content`、`code`、`site`、`lifecycle` の部分集合で、キー作成時に
   選択します。

キーは、その所有者のシートより多くのことは決してできません。ワークスペースポリシーでロールを狭めると、その人が作成した
すべてのキーも狭まります。所有者が持たないスコープをキーに付与しても何も付与されません（呼び出しは
`403 TOOLSET_NOT_GRANTED` を返します）。owner のキーであっても `scopes: ["content"]` ではコードを変更できません。

読み取りには、正しいサイト上の有効なキーと少なくとも 1 つのスコープが必要です。`records` ルートは生のサーフェス
（CMS 自身の行）であり、`pages`、`contents`、`changes` ルートは同じサイトの Content API ビューです。
どちらも同じ方法でチェックされます。

## キーの送信

```http
GET /v1/sites/shop.example.com/pages HTTP/1.1
Host: api.tracy.ai
Authorization: Bearer trk_xxxxxxxxxxxxxxxx.yyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyy
```

- スキームは `Bearer`、ヘッダーは `Authorization`、キーは
  `trk_<id>.<secret>` 文字列の全体です。
- **Bearer のみ、API ホスト上のみ。** `api.tracy.ai` はセッション cookie を読み取りません。
  `cowork.tracy.ai` のブラウザーセッションはここでは資格情報ではなく、cookie を運ぶリクエストは何も運んでいないものとして
  扱われます。キーが欠けているか形式が不正な場合は `401 KEY_INVALID` を返します。
- Tracy 自身のホスト名（`cowork.tracy.ai`）に送られたキーは無視されます。それらのルートはセッション
  cookie またはエージェントの署名付きアサーションを受け取り、キーは決して受け取りません。
- Tracy エージェントが会話を識別するために使うヘッダー（`x-tracy-session`、`x-tracy-actor`、
  `x-tracy-workspace-label`）は `/v1` リクエストから **削除されます**。2 人の書き込み者を 1 つのサイトから
  引き離すリースは、キー自身の識別子（`key:<id>`）の下で保持され、サーバーが決定します。

## ライフサイクル

| イベント | 効果 |
|---|---|
| 作成 | 完全なキーが一度だけ表示されます。Tracy はハッシュ（サーバー側ペッパー付きの HMAC-SHA256）を保存し、シークレットを再表示することはできません。 |
| 使用 | `last_used_at` が更新されます（最大で 1 分に 1 回）。 |
| 期限切れ（`expires_at`、任意） | すべての呼び出しが `401 KEY_EXPIRED` を返します。 |
| 所有者による取り消し | すべての呼び出しが `401 KEY_REVOKED` を返します。**取り消しは永続的です** — 後でシートを再付与してもキーは戻りません。 |
| 所有者のシートの取り消し | すべての呼び出しが即時に `403 SEAT_NOT_AUTHORIZED` を返します。シートはリクエストごとにチェックされ、キャッシュされません。 |
| サイトの削除 | キーもともに削除されます。 |

キーは Tracy の Settings で管理するか、Tracy 自身のホスト名上のアカウントドア
（`GET /api/me/keys`、`POST /api/me/keys`、`DELETE /api/me/keys/{id}`）を通じて管理します。これらはブラウザー
セッションを受け取り、キーは決して受け取りません。

## キーをフロントエンドに埋め込まないでください

キーは、あなたのシートと同じ範囲に届くシークレットです。サーバー上、CI のシークレット、またはローカルツールに
保管し、ページ、モバイルアプリ、公開リポジトリには決して置かないでください。API は `/v1` で、ブラウザーからの呼び出しにはただ一つのオリジン（[リファレンス](/ja/reference/)の **Test request**
ボタンのための、このドキュメントのオリジン）にのみ応答し、資格情報（credentials）付きでは決して応答しません。
そのため、別のオリジン上のページが誤ってでもキー付きで呼び出すことはできません。**Test request** は何も保存しません。
そこに入力したキーはそのタブ内にのみ存在します。

## レート制限

制限はキーごとに 2 つのバケットで課され、呼び出しがサイトに届く前にカウントされます。

| バケット | 制限 | カウント対象 |
|---|---|---|
| read | 1 時間あたり 6,000 | 何も変更しないすべてのルート |
| write | 1 時間あたり 600 | サイトを変更するすべてのルート（`PATCH`、`DELETE`、`POST …/contract/*`、`POST …/revert`） |

制限を超えると応答は `429 RATE_LIMITED` となり、次のウィンドウが開くまでの秒数を示す `Retry-After` ヘッダーが
付きます。カウンターはフェイルクローズです。読み取れない場合、呼び出しは通過させられるのではなく拒否されます。

## この層のエラーコード

| ステータス | コード | 意味 |
|---|---|---|
| 401 | `KEY_INVALID` | `Authorization: Bearer trk_…` がない、キーが存在しない、またはシークレットが一致しない。 |
| 401 | `KEY_REVOKED` | キーが取り消された。新しいキーを作成してください。 |
| 401 | `KEY_EXPIRED` | キーの `expires_at` を過ぎた。新しいキーを作成してください。 |
| 403 | `SEAT_NOT_AUTHORIZED` | キーの所有者がこのサイト上に有効なシートを持っていない（シートが取り消された、またはパスが別のサイトを指している）。 |
| 403 | `TOOLSET_NOT_GRANTED` | アクションに必要なツールセットが、キーのスコープ ∩ シートの権限の外にある。応答には `toolset` と `role` が示されます。 |
| 429 | `RATE_LIMITED` | 2 つのバケットのいずれかを超えた。`Retry-After` 秒待ってください。 |

その他すべての拒否（サイト自身の応答を含む）は[エラー](/ja/reference/errors/)
ページにあります。
