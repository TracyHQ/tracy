## 5 分でできること

1. シートを持つサイトの **Settings → API keys** で API キーを作成します。
2. `GET /v1/me` — キーが誰として、どのサイト上で、どのスコープで動作するかを確認します。
3. `GET /v1/sites/{key}/pages` — サイトの公開済みページとそのコンテンツ id を一覧します。
4. `PATCH /v1/sites/{key}/records/{kind}/{id}` — タイトルを 1 つ変更し、`apply_id` の下に記録します。
5. `POST /v1/sites/{key}/applies/{apply_id}/revert` — それを元に戻します。

[クイックスタート](/ja/quickstart/)では、まさにこの 5 つの呼び出しを `curl` で順に実行します。

## システムの構成

```text
Bearer trk_…  (you, your agent, a partner's integration)      cookie tracy_sess (a browser on cowork.*)
      |  /v1/*  — Bearer only, no cookie                              |  /api/sites/{key}/apply, /api/me/keys
  api.tracy.ai ── API host ── allowlist ──┐                           |
                 └─ /docs/api/<document>   (this site: docs.tracy.ai) |
                                          ▼                           ▼
                        applyDoor(siteKey, action, params, principal)   ← ONE path: seat · effective permissions ∩ scopes · lease · audit
                                          |
                  Claude Cowork plugin (Joomla, WordPress) · Tracy reader (EmDash)
```

- **`api.tracy.ai`** は `/v1/*` と、`/docs/api/` 以下の機械可読な 3 つのドキュメント（OpenAPI、Claude Cowork プラグイン、llms.txt）に応答します。このドキュメントとインタラクティブなリファレンスは **`docs.tracy.ai`** にあります。それ以外は何もありません。サインイン、ワークスペース、Ops ツールは Tracy 自身のホスト名上にあり、どちらのホストでも `404 NOT_ON_THIS_HOST` を返します。
- **1 つのドア。** すべての `/v1` ルートは Apply ドアのアクションの薄いエイリアスであり、Tracy エージェントが通るのと同じ経路です。あなたが誰か（キーの所有者）、シートが何を許可するか、サイトの書き込みリース、そして監査ログ。
- **サイトが応答します。** Joomla と WordPress では、呼び出しはサイトにインストールされた Claude Cowork プラグインに届きます。EmDash では Tracy 自身のリーダーに届きます。サイトが拒否したものは、文書化された[エラー](/ja/reference/errors/)として返されます。
