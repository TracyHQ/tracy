# Acceptance, packaging and recovery

Read ../AGENTS.md. Regenerate the inventory after source changes with `node tools/generate-docs.mjs`; `--check` verifies completeness and freshness only. Regenerate `artifact.json` with `node tools/artifact.mjs` after documentation changes; the package ships it.

- Unit tests: `node --test tests/*.test.mjs` (takes about four minutes; some tests need Playwright's Chromium: `pnpm exec playwright install chromium`, once per machine, as does `pnpm test`). Types: `pnpm typecheck`.
- Seed check: `node tools/validate-seed.mjs`; seed rebuild from the model: `ingest/rebuild-seed.sh`. Content API gate: `node tools/content-api-gate.mjs`.
- Acceptance: `node tools/qa.mjs --help` lists the run (contract `tools/qa-contract.mjs`, receipt `tools/qa-receipt.mjs`, visual `tools/visual-qa.mjs`, gates read with `node tools/gates.mjs <run>`). `qa.contract.json` and the design folder the run compares against (`--source`) do NOT ship in the pack: the acceptance run is made from the Tracy repository checkout, not from the package alone. The acceptance evidence of the port is kept outside it, in the owner's work folder.
- Audit of a running site (about a minute): `node tools/audit.mjs <base-url> <out-dir>`, for example `node tools/audit.mjs http://127.0.0.1:4361 ./audit-out`. `--roots` is optional: it defaults to `/` for this English-only template, and `--roots /` says the same. The audit exits 1 on any finding and writes `audit.md` (the readable report: one row per page with status, kind, h1, canonical and hreflang) and `audit.json` (the same data) to the out folder. Kinds: `indexable` (a page that must not be `noindex` and must name its own canonical address), `noindex` (the search page, which must be `noindex`), `unknown` (addresses that must not exist: a 404 listed there is the expected answer, a 200 is a finding). The crawl follows `?start=` and `?category=` addresses too.
- Admin round trip (opens the admin in a browser, edits one field, saves, publishes, checks the public page, restores the original and checks it is back; it leaves no residue). Use a throwaway site (`tools/clean-install.sh <dir> <port>`), never a customer's. Needs Playwright's Chromium (`pnpm exec playwright install chromium`, once per machine). Recipe, in this order, all from the new site's folder (`clean-install.sh` leaves you in the folder you started from; `cd <dir>`, because the commands below use `data/tracy-agent.token` and `state.json` relative to it):
  1. Start a mail catcher: `docker run -d --name nova-mailpit -p 127.0.0.1:1025:1025 -p 127.0.0.1:8025:8025 axllent/mailpit`. If ports 1025 or 8025 are taken (another catcher already runs: `docker ps`), reuse that one, or stop it, or map other host ports and pass the SMTP port to `configure-smtp.mjs` (`--port <smtp port>`; its other options, `--host`, `--security`, `--from`, `--from-name`, `--test <address>`, are listed in the comment at the top of the script; `--help` is not supported) and the catcher's web port to `admin-session.mjs` in step 3 (`--mailpit http://127.0.0.1:<web port>`; without it the script waits for the sign-in mail on 8025 and fails with a bare `fetch failed`).
  2. Point the site's mail at it: `node tools/configure-smtp.mjs --site http://127.0.0.1:<port> --token-file data/tracy-agent.token`.
  3. Sign in: `node tools/admin-session.mjs --site http://127.0.0.1:<port> --email tracy-agent@tracy.ai --out state.json`.
  4. Find the target entry id: `curl -s -H "Authorization: Bearer $(cat data/tracy-agent.token)" -H "X-EmDash-Request: 1" http://127.0.0.1:<port>/_emdash/api/content/pages/about` and read `data.item.id`.
  5. Run `node tools/admin-roundtrip.mjs --site http://127.0.0.1:<port> --storage-state state.json --entry /_emdash/admin/content/pages/<id> --field field-title --public /about --out roundtrip.json`. Field ids are `field-<name>` (`field-title`, not `title`). The About page's title is a safe target; the tool restores the original value. The edit is visible on the public page only between the save and the restore; the tool checks it there and puts the original back. To keep a change, edit the entry in the admin (Admin > Content) and publish it, or write it through the Content API (`docs/content-api.md`).
  6. Clean up: stop the catcher (`docker rm -f nova-mailpit`) and the site. `clean-install.sh` starts the server in the background in the site folder: its output is `server.log` there, and `lsof -ti tcp:<port>` gives its process (`kill` it to stop).
- Backup: `tools/backup.sh [data] [uploads] [out]` writes `backups/tracy-nova-<stamp>.tgz` (SQLite, uploads, receipts, the agent token: keep it private). Restore: stop the site, then `tools/restore.sh <archive>`; it validates the archive and moves the current state aside as `*.before-restore-<stamp>`. `tools/recovery-check.mjs` proves the round trip on a RUNNING site you own, from the site folder: `node tools/recovery-check.mjs --site <origin> --token-file data/tracy-agent.token --collection pages --slug about --field title --public /about --out recovery.json` (optional `--locale en`, `--port <n>`); it stops and restarts the server itself, so never run it on a site someone is using. `restore.sh` and `backup.sh` also run from a site folder with its dependencies installed (`better-sqlite3` is read from `node_modules` there); elsewhere `restore.sh` reports the archive as "not a valid SQLite database" although it is fine. The encryption key (`EMDASH_ENCRYPTION_KEY`, an environment variable of the site that the local scripts do not create) must be kept with the data or plugin secrets are lost.
- Export source only by the allowlist (`node tools/distribution.mjs pack <contract> <new-directory>`, checked by `verify <artifact-directory>`); never customer databases, uploads, secrets, tokens, backups or `*.before-restore-*` directories.
- Known blockers and owner decisions are kept in the Tracy repository (`STATUS.md`, `DECISIONS.md`), not in this package; ask the owner for them.
