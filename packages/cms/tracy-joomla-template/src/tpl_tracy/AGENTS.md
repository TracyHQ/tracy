# tpl_tracy: instructions for agents

Read this file before changing anything on this site. It describes the **installed Joomla site and
its template**, not the package that produced them: a maintenance agent may receive only this
webroot and this database, with no access to the build workspace or the conversation that made it.

Template: **`tpl_tracy`**, version in `templateDetails.xml` (0.1.0 at the time of writing). It is
the template behind the quickstart **`tracy-base/j6`** — the contract for that quickstart names it
as `tracy`, which is the template *style* name a site sees; the folder is `templates/tracy`.

⚠ **`tpl_tracy` is not `tracy_business`.** They are two different templates with two different
sets of rules: `tracy_business` is a JoomlArt **T4** template with ACM blocks and its own
thirteen-rule `AGENTS.md`. Nothing on this page applies there, and nothing there applies here.
Check which one the site runs before reading either — `content.list` kind `templateStyle`, or the
`templates/` folder.

## Rules

1. **Every file of this template is generated by a build** (`scripts/build.mjs` of
   `@tracy/joomla-template`, gated by `--check`). A hand edit on the installed site is lost at the
   next package update, silently — no error, and the site keeps working until it lands. What is
   site-specific belongs in the database: a template **style**, a module, a menu item's params.
2. **Colours, type and spacing are tokens, and the tokens are generated.** `media/css/inspirations/`
   carries **154** token files, one per design system, written from `vendor/tracy/od-design-system`;
   `inspirations.json` says it in its own note — *"do not edit; rerun the build"*. Which one a site
   wears is a **parameter of its template style**, not a file to edit. Typing a hex value over a
   token creates a second source of truth that the next build discards.
3. **Layout changes are overrides, under `html/`** — never a core file and never an extension's own
   views, both of which the next Joomla update replaces. This template ships **19** override files
   across `com_content`, `com_contact`, `mod_menu` and `layouts`.
4. **Five positions, and only five**: `nav`, `hero-aside`, `sidebar`, `footer`, `debug`. A module
   assigned to a position this template does not declare renders nowhere, and nothing reports it.
5. The page **sections** (17 files under `sections/`) are the template's own markup. They are not a
   block catalogue an editor can rearrange: a section is chosen by the page it belongs to. Do not
   paste section markup into an article — the article keeps it, the template stops owning it, and
   the next update leaves the two out of step.
6. **Words live in the database**, not in these files: articles, menu items, and module text —
   which is often a module **parameter** rather than its body. Read them through the content door,
   never by editing the database directly: raw SQL skips the receipt, the undo and the nested-set
   upkeep, and leaves a site that looks fine over broken data.
7. **Phrases Joomla ships are a language pack first.** `language/` here holds only this template's
   own strings. For everything else, install the pack (`extension.install {url}` — the site
   downloads it itself) and write an override only for what the pack does not cover: one
   `KEY="value"` line in `language/overrides/<tag>.override.ini`, never an edit to a shipped `.ini`.
8. Do not fabricate business facts, legal text, people, prices or images. A gap is recorded, not
   filled.
9. **Clear the cache after any change** (`php cli/joomla.php cache:clean`). "My change does nothing"
   is almost always this. The admin is at `/administrator`, and a maintenance agent cannot open it.
10. Report separately: what changed in files, what changed in the database, which checks ran, and
    what could not be verified.

## What this template is made of

Measured from this tree:

| | |
|---|---|
| positions | **5** — `nav` · `hero-aside` · `sidebar` · `footer` · `debug` |
| overrides (`html/`) | **19** — `com_content` · `com_contact` · `mod_menu` · `layouts` |
| sections | **17** |
| design-system token files | **154**, under `media/css/inspirations/` |
| language | this template's own strings only |
| entry points | `index.php` · `component.php` · `resolve.php` · `motion-head.php` |

⚠ These describe the template's **files**. Which modules exist, which style is active and what a
page actually contains are facts about *this database* — discover them from the site itself.

## Where each kind of change goes

| you want to change | it lives in | door |
|---|---|---|
| the words on a page | article · menu item · module **params** | the content door |
| the site's design system | the template **style**'s parameter | the content door, kind `templateStyle` |
| where a module appears | its position, from the five above | the content door |
| the markup of a listing or a menu | `html/` override | file |
| a phrase Joomla ships | the language **pack** first, then an override | `extension.install`, then `.override.ini` |
| a colour, a font, a space | the design system, then rebuild | never a token file by hand |
