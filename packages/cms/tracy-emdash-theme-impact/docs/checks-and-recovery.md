# Acceptance, packaging and recovery

Read ../AGENTS.md. Regenerate the inventory after source changes with `node tools/generate-docs.mjs`; `--check` verifies completeness and freshness only. Regenerate `artifact.json` after documentation changes.

- Unit tests: `node --test tests/*.test.mjs` (some need Playwright's Chromium: `pnpm exec playwright install chromium`; some read repository-only files and skip in the package). Types: `pnpm typecheck`.
- Acceptance (repository checkout): `node tools/qa.mjs --contract qa.contract.json --source source/snapshot --site <origin> --out evidence/qa-1 --browser --visual --visual-fast-gate <fast-gate run>`; gates are read with `node tools/gates.mjs <run>`. Evidence stays outside the package.
- Verify a package folder: `node tools/distribution.mjs verify .` (run inside the package; a pass prints `status: pass` and `errors: []`; it checks the package files, not an installed site).
- Install a site from the package: `bash tools/clean-install.sh <new-dir> <port>`. It builds the site and leaves the server RUNNING in the background (its log is `<new-dir>/server.log`; stop it by ending the process that listens on `<port>`, for example `ss -ltnp | grep :<port>`). It needs Playwright's Chromium only for the browser tools below (`pnpm exec playwright install chromium`).
- Smoke test of a running site: the pages `/`, `/about`, `/donations`, `/donations/community-center`, `/events`, `/events/feed-the-world`, `/blog`, `/help-faqs`, `/contact`, `/search?q=water` answer 200 and a missing path such as `/nope` answers 404.
- Routing audit: `node tools/audit.mjs <base-url> <out-dir>` (optional `--config template.config.json`); a pass exits 0 and prints a JSON line with `complete: true` and `findings: 0`.
- Mail sandbox and admin sign-in: start Mailpit on 127.0.0.1:8025/1025, then `node tools/configure-smtp.mjs --site <origin> --token-file data/tracy-agent.token --test <address>` and `node tools/admin-session.mjs --site <origin> --email tracy-agent@tracy.ai --out admin-state.json`.
- Admin round trip (edit a field through the admin, prove the public page changes, restore): get an entry id with `curl -H "Authorization: Bearer $(cat data/tracy-agent.token)" "<origin>/_emdash/api/content/events?limit=50"`, then `node tools/admin-roundtrip.mjs --site <origin> --storage-state admin-state.json --entry /_emdash/admin/content/events/<id> --field field-title --public /events/<slug> --out roundtrip.json`. `node tools/forms-check.mjs <origin> admin-state.json forms.json` checks both forms and the mail.
- Backup: `tools/backup.sh [data] [uploads] [out]` writes `backups/tracy-impact-<stamp>.tgz` (SQLite, uploads, receipts, the agent token: keep it private). Restore: stop the site, then `tools/restore.sh <archive>`; it validates the archive and moves the current state aside as `*.before-restore-<stamp>`. `tools/recovery-check.mjs` proves the round trip. The encryption key (`EMDASH_ENCRYPTION_KEY`) must be recovered with the data or plugin secrets are lost.
- Export source only by the allowlist (`node tools/distribution.mjs pack`); never customer databases, uploads, secrets, tokens, backups or `*.before-restore-*` directories.
- Known gaps and the decisions behind the template are kept in the repository checkout (STATUS.md and DECISIONS.md); they are not part of this package.
