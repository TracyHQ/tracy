# JA Kinetic: instructions for agents

Read this file before changing anything on this site. It describes the **installed WordPress
site and its theme**, not the Tracy skill (`tracy-wordpress-theme`) that produced them: a
maintenance agent may receive only this webroot and this database.

Theme: **WP Kinetic**, slug `wp-ja-kinetic`, text domain `wp-ja-kinetic`, version in `style.css`
(`Version:` is stamped at build). Requires WordPress 7.0 and PHP 8.1; built and verified on
WordPress 7.1 / PHP 8.3. The site it carries is "Kinetic — observability, reimagined", ported from
the JoomlArt Joomla 6 quickstart `quickstart/ja-kinetic/j6` so that it renders the same pages; the
WordPress quickstart is released under the tag `quickstart/ja-kinetic/wp7`.
Dependency: **AcyMailing** (`acymailing`) — the footer's newsletter form is its block.

## Rules

1. This is a WordPress **block theme**. Templates, parts and patterns are files under
   `wp-content/themes/wp-ja-kinetic/`; the site's words are rows in the database. Read
   docs/architecture.md before touching either.
2. Identify the target before any command: `wp option get siteurl`, `wp theme list --status=active`
   (expect `wp-ja-kinetic`), the webroot path and the process owner. Never assume a localhost stand.
3. Content is edited **through WordPress** — the editor, `wp post update`, or the REST API — as
   block markup. Do not edit the SQL dump, and do not paste a whole page into one `core/html`.
   Read docs/content-model.md for where each kind of text lives.
4. Every file of the theme is **generated by a build** (`@tracy/wordpress-theme`, target
   `wp-ja-kinetic`) and replaced whole by the next theme update. A hand edit to `theme.json`,
   `styles/*.json`, `patterns/`, `templates/`, `parts/`, `blocks/`, `assets/` or `inc/` on the
   installed site is lost silently. Site-specific overrides go where WordPress keeps them: the
   Site Editor (templates, parts and styles become database rows) or a child theme.
5. A section inserted into a page is a **copy**: editing the page changes that page only. Two
   **synced patterns** (`wp_block` `wp-ja-kinetic-cta-blog`, `wp-ja-kinetic-cta-article`) carry the
   call-to-action band of the blog and article views: editing one changes every place it appears.
6. The header and footer are **database rows** (`wp_template_part` `header` and `footer`). They
   shadow `parts/*.html`: editing the files changes nothing until the rows are deleted.
7. Much of what a page shows comes from **post meta** written by the port's post-seed step
   (direction, light/dark default, which view a page draws, bylines). Read docs/content-model.md
   before moving, renaming or re-templating a page.
8. Do not fabricate business facts, legal text, people, prices or images. Everything on the site
   is demonstration data until the owner replaces it; a gap is recorded, not filled. Read
   docs/content-rules.md.
9. Back up before a structural change (`wp db export`, and `wp-content/uploads`). The quickstart
   is the site **as built**, not a rollback target for an edited site. Read docs/checks-and-recovery.md.
10. Report separately: what changed in files, what changed in the database, which checks ran,
    and what could not be verified.
