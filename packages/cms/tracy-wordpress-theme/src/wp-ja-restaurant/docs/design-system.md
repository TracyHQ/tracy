# Design system

Read ../AGENTS.md. JA Restaurant is **not** one of the vendored catalogue design systems (`variations` is
empty in `theme.config.json`). Its look has two layers: the **template's own stylesheets**, carried rule
for rule (D-10), and a token set **measured** on the running source (`tasks/ja-restaurant-wp7/design-contract.json`
in the Tracy repository) that becomes `theme.json`. A value the source did not give comes from the
`apple` design system (`tokens.css` of the build: 19 measured, 1 derived, 36 fallback, 11 lines set by
hand for tool issue S-5). The root variation is `styles/wp-ja-restaurant.json` ("WP Restaurant"); no
other variation ships. Do not edit any file below by hand except through the Site Editor's Styles.

## Where each thing lives

| Layer | File | Edit by hand? |
| --- | --- | --- |
| Tokens | `tokens.css` (overlay build source, not in the installed theme) | no: written by `theme-tokens.mjs` from the design contract |
| `theme.json` (16 colour presets, fonts `display`/`body`/`mono`, 8 sizes, 8 spacing steps, layout 1190 px) | generated from `tokens.css` and `theme.overlay.json` | no |
| Dark half of the colours | `theme.overlay.json` `styles.css` (`light-dark()` presets) | no: change the build source and rebuild |
| The source template's sheets | `assets/css/source/{bootstrap,template,megamenu,off-canvas}.css` and `source/acm-*.css` (11 files) | **no**: generated by `tasks/ja-restaurant-wp7/tools/port-css.mjs`; every colour is `light-dark(<source>, <derived dark>)`, every `url()` points at `assets/img`; re-run the tool |
| WordPress adaptations | `assets/css/wp-ja-restaurant.css`, `groups/{about,account,article,blog,home,menus}.css`, `fonts.css`, `icons.css` | no: theme files, replaced by a theme update |
| Owner overrides | Site Editor > Styles (the `wp_global_styles` row) | yes |

Palette (light / derived dark, D-03): page `#f4f2e7` / `#1c1a17`; boxes `#ffffff` / `#26231f`; menu and
footer band `#3a352f` / `#11100e`; body text `#3a352f` / `#e9e4d6`; headings `#333333` / `#f0ece2`; muted
`#555555` / `#b5ad9e`; meta `#999999` / `#8f877a`; border `#cccccc` / `#544e46`; accent `#d24a24` and the
yellow hover `#ffd33d` in both. Each preset reads a design-system role first
(`var(--ds-c-bg, #f4f2e7)` …, `theme.config.json` `roleReads`): when Tracy dresses the site in a design
system, its colours win; without one the template's own show. `inc/role-reads.php` hands the editors the
plain fallback colour so the Site Editor's colour picker works.

Type: Teko (display: headings, titles), Noticia Text (body; its 400 latin file is preloaded), Roboto Mono
(menu, buttons, module titles); Saira Extra Condensed replaces Teko on `:root:lang(vi)` pages (D-04). All
bundled under `assets/fonts` (D-12). Icons: Font Awesome 4.6.3 (`fa-*`) and Ionicons 2.0.0 (`ion-*`).
Grid: Bootstrap 3 containers 768 / 990 / 1190 px from 768 / 992 / 1200 px (`source/bootstrap.css`).

## Header, navigation and body classes

`parts/header.html`: a top bar with the opening hours (`header.open-time`), the centred logo (two Site
Logo blocks, `jr-logo--light` and `jr-logo--dark`), and the menu band `t3-mainnav` holding the main menu
(`nav.mainmenu`, submenus open on hover), the dark-mode toggle and, on phones, a button that opens the
side panel `#jm-off-canvas` with the same menu. `inc/extra.php` forces the body classes
`tracy-nav-top-left` and `tracy-hero-split` (overriding the generic `brand-centered`/`cover` of
`theme.config.json`) so no catalogue layout moves the header; pages also carry `jm-route-<slug>` and
`jm-parent-<slug>`, which the group stylesheets key on (renaming a page slug can change its look).

## Logos

WordPress core has one logo (`site_logo`). `inc/brand-logo.php` adds `tracy_logo_dark` (an attachment id)
for the dark-background spot `jr-logo--dark`; when it is unset that spot prints the site name as text
(class `is-tracy-logo-text`). At build time `site_logo` is the source's `logo.png` and `tracy_logo_dark` is
unset (D-08, open). Set it with `wp option update tracy_logo_dark <attachment id>`.

## Dark mode

The source has no dark mode; the switch and the dark palette are the port's (D-03). The page is light or
dark and a click flips whichever is showing. The choice is kept in the cookie `tracy_theme` (one year,
path `/`). Light and dark are `data-theme` on `<html>`; **no attribute** (no cookie yet, or an `auto`
cookie) leaves `color-scheme: light dark` in charge, so the OS decides (`prefers-color-scheme`).
`assets/js/wp-ja-restaurant-dark.js` runs in the head, blocking, so a visitor who chose dark never sees a
light frame; the toggle (`[data-tracy-theme-toggle]`) labels itself from what the page shows.
`?theme=dark|light` wins for that load and is never saved (the first value decides; `inc/extra.php`
stops WordPress's canonical redirect from changing it). WordPress core has no colour-scheme mechanism;
this follows https://developer.wordpress.org/news/2025/09/building-a-light-dark-mode-toggle/.

To test: set `data-theme="dark"` on `<html>`, or click the toggle and reload (the cookie must persist).

## Switching and previewing a look

- Site Editor > Styles: the one shipped look; owner changes land in the global-styles row.
- `wp eval 'tracy_apply_inspiration("<id>");'` writes a design system to global styles without a login;
  `?style=<id>` previews one for this visitor only (cookie `tracy_style`, a day). See
  https://developer.wordpress.org/themes/global-settings-and-styles/style-variations/.

## Motion

`tracy_motion` defaults to one effect, `carousel-step`: the slideshow, the home quotes carousel and the
gallery slide step when the visitor uses the arrows or buttons. No scroll reveal (the source runs none).
Vertical "fixed" backgrounds are drawn with `position: fixed` pictures; horizontal parallax is not carried
(D-11). A back-to-top button appears after 200 px of scrolling on screens 992 px and wider.

## Rules for changes

- Colours by preset (`var(--wp--preset--color--…)`), never a raw hex in a new rule.
- Never hand-edit `assets/css/source/`; a fix there is a change to `port-css.mjs` or to
  `wp-ja-restaurant.css`.
- No reset or framework added to the page; the stylesheets answer to the source's class names.
- A new section: insert an existing pattern from the editor; do not edit `patterns/*.php` on a live site.
