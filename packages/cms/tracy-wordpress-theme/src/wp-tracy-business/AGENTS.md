# Tracy Business: instructions for agents

Read this file before changing anything on this site. It describes the **installed WordPress site
and its theme**, not the Tracy skill (`tracy-wordpress-theme`) that produced them: a maintenance
agent may receive only this webroot and this database, with no access to the build workspace, the
spec-pack or the conversation that made it.

Theme: **Tracy Business**, slug and text domain `wp-tracy-business`, version in `style.css`
(`Version:` is stamped at build — read it there, not from this file). Requires WordPress 7.0 and
PHP 8.1. It ships as quickstart **`tracy-business/wp7`** (release tag in
`JoomlArt-Products/ja-products`). The theme updates itself from its `Update URI`
(`TracyHQ/claude-cowork`), which is why rule 4 below matters.

Dependencies the theme reads (`inc/extra.php`): **Polylang** for the language switcher and the
per-language menus, and **Contact Form 7** (`wpcf7`) for the contact page's form and the news sidebar's subscribe card (the form titled `Newsletter`; the card is left out without it). A site missing
either still renders; the feature that needs it simply does not appear, which is the quietest way
to be told something is wrong.

## Rules

1. This is a WordPress **block theme**. Templates, parts and patterns are files under
   `wp-content/themes/wp-tracy-business/`; the site's words are rows in the database. Decide which
   of the two you are changing before you change it — the same visible result is reached two
   different ways, and picking the wrong one edits a file nobody reads.
2. Identify the target before any command: `wp option get siteurl`,
   `wp theme list --status=active` (expect `wp-tracy-business`), the webroot path and the process
   owner. Never assume a localhost stand.
3. Content is edited **through WordPress** — the editor, `wp post update`, or the content door —
   as block markup. Do not edit the SQL dump, and do not paste a whole page into one `core/html`:
   a page built that way is invisible to every later edit and to the pattern catalogue.
4. Every file of this theme is **generated by a build** (`@tracy/wordpress-theme`, target
   `wp-tracy-business`) and replaced whole by the next theme update, which the theme fetches by
   itself. A hand edit to `theme.json`, `styles/*.json`, `patterns/`, `templates/`, `parts/`,
   `assets/`, `blocks/` or `inc/` on the installed site is **lost silently** — no error, no
   warning, and the site keeps working until the update lands. Site-specific overrides go where
   WordPress keeps them: the Site Editor (templates, parts and styles become database rows) or a
   child theme.
5. **Colours, type and spacing are tokens, and the tokens are generated.** `theme.json` and
   `styles/wp-tracy-business.json` come from a design system
   (`inspirations.json` says so in its own `note`: *"do not edit; rerun the build"*). Typing a hex
   value over one of them creates a second source of truth that the next build discards. Change
   the design system or accept the token.
6. A section inserted into a page is a **copy**: editing the page changes that page only. A synced
   pattern (`wp_block`) is the opposite — editing it changes every place that references it. Know
   which one you are holding before you edit.
7. The header and footer may be **database rows** (`wp_template_part`) that shadow
   `parts/header.html` and `parts/footer.html`: when they exist, editing the files changes nothing
   until the rows are deleted. Check before concluding an edit did not work.
8. **Many languages, through Polylang.** The quickstart ships 41 languages; the build keeps the
   languages the owner chose and hides the others' pages, posts and menus. A post or page exists
   once per language and the copies are linked; a translation that is not linked is invisible to
   the switcher and to hreflang. Never machine-translate what the owner has not supplied — leave it
   unpublished and say so.
9. Do not fabricate business facts, legal text, people, prices or images. Everything on the site
   is demonstration data until the owner replaces it; a gap is recorded, not filled.
10. Back up before a structural change (`wp db export`, and `wp-content/uploads`). The quickstart
    is the site **as built**, not a rollback target for an edited site.
11. Report separately: what changed in files, what changed in the database, which checks ran, and
    what could not be verified.

## What the theme does while a page is drawn

Six things happen at render, on the page as it is served, not in the database. Knowing them saves
an edit that looks right in the database and wrong on the page, or the other way round.

1. **The site identity.** The site name, legal name, slogan, monogram, logo, contact details
   (address, phone, email, office hours) and social links live in **one option,
   `tracy_site_identity`**, written through the content contract (`content.contract`), not by the
   theme. The header, footer and Contact card carry tokens (`{site.name}`, `{contact.email}`, …)
   that `inc/identity.php` fills from that option on every page. An element marked with
   `data-tracy-identity="<field>"` is dropped when its field is empty; the demo value is never
   shown. The `<title>` takes its site name from the identity's name and the front page's tagline
   from its slogan; `blogname` and `blogdescription` stay what admin, mails and feeds print. Change
   a phone or an address once, in the option, and every page follows.
2. **The theme's words in the page language.** The fixed English words the theme prints — header,
   footer, sidebars, the 404, news, article and search pages — are swapped into the page language
   from the theme's own translation files (`languages/<locale>.l10n.php`). Only a word that still
   reads exactly as shipped is swapped: a word the owner rewrote stays as written, in every
   language.
3. **Links and menus per language.** A root-relative link typed into the header or footer
   (`/contact/`) goes to the same page in the page language. A navigation block named
   `nav.<kind>` shows the page language's own menu, the published `wp_navigation` post with slug
   `<kind>-<lang>`, and the base menu `<kind>` when that language has none. To change one
   language's menu, edit its `<kind>-<lang>` post; to change every language, edit each of them.
4. **The Sitemap.** The page using template `page-sitemap` lists the page language's menus, then
   its other published pages, then its news, built at render. The footer's Sitemap link is the
   `footer-legal` menu, so each language reaches its own Sitemap page. There is nothing to edit on
   the Sitemap page itself: publish, unpublish or rename the pages it lists.
5. **The Contact page.** Its contact card shows the identity's address, phone, email and office
   hours (point 1); a row whose field is empty is dropped, and the card is dropped when all four
   are empty. Its labels (Address, Hotline, Email, Office hours) show in the page language. Every
   language's Contact page embeds **the same Contact Form 7 form**; its labels, button, upload,
   hint and consent lines, request types and description hint are shown in the page language, and
   its sent / error messages follow the page it was sent from. Change the form once, in English:
   there is no per-language copy to keep in step, and a word changed there is no longer translated.
6. **The news band.** The section `wp-tracy-business/section-news` (the front page's "News &
   disclosures") is a Query Loop: its cards are the page language's three latest published posts,
   drawn from the posts at render. To change a card, edit the post — its title, excerpt, featured
   image or category; a new post takes the first card by itself. Only the band's head (eyebrow,
   heading, intro, "View all") is text in the page. "View all" goes to the page language's posts
   page (Settings → Reading) while its link is still `#`; a link typed there is kept. While the
   page language has no published post the whole band is left out of the page. ⚠ A front page
   built before 28/09/2026 may still carry the band as three typed cards (blocks named
   `news.item.<n>`): those are copies in the page, not posts, and do not follow the posts.

## Where each kind of change goes

| you want to change | it lives in | door |
|---|---|---|
| the words on a page or post | the database | the editor · `wp post update` · the content door |
| the site name, slogan, contact details or social links | option `tracy_site_identity` | the content contract (`content.contract`) — **not** a theme file |
| the words the theme prints in one language | `languages/<locale>.l10n.php` | a theme file, see rule 4 |
| a menu | the database: one `wp_navigation` post per kind and language (`<kind>-<lang>`) | the editor |
| the Contact form | one Contact Form 7 form, shared by every language | the Contact Form 7 screen |
| the layout of a page type | `templates/*.html` — or the Site Editor row that shadows it | see rules 4 and 7 |
| header or footer | `parts/*.html` — or the `wp_template_part` row that shadows it | see rule 7 |
| a reusable section | `patterns/*.php` | see rule 6 |
| a colour, a font, a space | the design system, then rebuild | see rule 5 |
| a phrase WordPress or a plugin ships | the locale's own translation first; only the remainder is a translation file or a `gettext` filter | never edit a shipped `.po`/`.mo` |
