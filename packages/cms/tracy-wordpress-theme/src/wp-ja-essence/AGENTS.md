# JA Essence: instructions for agents

Read this before changing anything. It describes the **installed WordPress site and its theme**,
not the Tracy skill that produced them.

Theme: **WP Essence**, slug `wp-ja-essence`, text domain `wp-ja-essence`, version in `style.css`
(1.0.0 when these documents were written). Requires WordPress 7.0 and PHP 8.1; built on 7.1.2. The
site is "JA Essence", an editorial blog (cards, category listings, article pages) ported from the
JoomlArt Joomla 6 quickstart for template `ja_essence` (T4 framework) so that it renders the same
pages. The theme requires no plugin; the seeded site also runs Contact Form 7 and three must-use
plugins (docs/install.md).

## Rules

1. This is a WordPress **block theme**: templates, parts and patterns are files under
   `wp-content/themes/wp-ja-essence/`, the site's words are database rows (docs/architecture.md).
2. Identify the target first: `wp option get siteurl`, `wp theme list --status=active` (expect
   `wp-ja-essence`), the webroot path and the process owner. Never assume a localhost stand.
3. Edit content **through WordPress** (editor, `wp post update`, REST API) as block markup; never a
   SQL dump, never a whole page pasted into one `core/html`. Where text lives: docs/content-model.md.
4. Every theme file is **generated by a build** (`@tracy/wordpress-theme`, target `wp-ja-essence`)
   and replaced whole by the next update: `theme.json`, `styles/*.json`, `inspirations.json`,
   `patterns/`, `templates/`, `parts/`, `assets/`, `inc/`. A hand edit is lost silently; overrides
   go in the Site Editor (database rows) or a child theme.
5. The header and footer are theme parts, and the seeded site **already holds** `wp_template_part`
   rows for both (`header`, `footer`) that shadow `parts/*.html`: edit those rows, or delete them
   to fall back to the files. Check before editing a file.
6. A section inserted into a page is a **copy**: editing the page changes that page only. A new
   section goes in from the editor (Patterns > JA Essence, `wp-ja-essence/*`); locate blocks by
   `metadata.name` (`<type>.<field>[.<n>]`, e.g. `gallery.title`), never by position. No synced
   pattern (`wp_block`) exists on the site.
7. Some behaviour hangs on **slugs, ids and options**, not on blocks: the page paths (`/pages/...`,
   `/category/...`, `/detail/...`), the draft `smart-search` page, the article route
   `/category/category-style-3/vintage-inspired-martini-cocktail-glasses`, the `je-slug-<slug>`
   body class, the `topic` category base, term ids inside the category pages' queries, and the
   redirect rules in `wp_ja_essence_redirects`. Read docs/content-model.md before renaming,
   moving, deleting or publishing a page or category.
8. Dark mode: the `tracy_theme` cookie (`light`, `dark`, or a 1.0.0 `auto`) applied as `data-theme` on
   `<html>`; no attribute = auto, the operating system decides; a click on the toggle flips what the
   page shows (docs/design-system.md).
9. Do not fabricate business facts, legal text, people, prices or images: everything on the site
   is demonstration data until the owner replaces it. Open decisions: docs/content-rules.md.
10. Back up before a structural change (`wp db export`, `wp-content/uploads`). No automatic theme
    update is offered: install a newer zip by hand (docs/checks-and-recovery.md). Report file
    changes, database changes, checks run and what could not be verified separately.
