# Tracy Base: instructions for agents

Read this file before changing anything on this site. It describes the **installed WordPress
site and its theme**, not the Tracy skill (`tracy-wordpress-theme`) that produced them: a
maintenance agent may receive only this webroot and this database.

Theme: **Tracy Base**, slug `tracy-base`, text domain `tracy-base`, version in `style.css`
(`Version:` is stamped at build). Requires WordPress 7.0 and PHP 8.1; built and verified on
WordPress 7.1 / PHP 8.3. The site it carries is the Tracy company site ("Tracy — Precision, in
every surface"), ported from the Joomla quickstart *Tracy Base j6*, and ships as quickstart
**`tracy-base/wp7`** 1.0.0 (release tag `tracy-base/wp7` in `JoomlArt-Products/ja-products`).
Dependency: **Contact Form 7** — the contact page's form is its `[contact-form-7]` shortcode.

## Rules

1. This is a WordPress **block theme**. Templates, parts and patterns are files under
   `wp-content/themes/tracy-base/`; the site's words are rows in the database. Read
   docs/architecture.md before touching either.
2. Identify the target before any command: `wp option get siteurl`, `wp theme list --status=active`
   (expect `tracy-base`), the webroot path and the process owner. Never assume a localhost stand.
3. Content is edited **through WordPress** — the editor, `wp post update`, or the REST API — as
   block markup. Do not edit the SQL dump, and do not paste a whole page into one `core/html`.
   Read docs/content-model.md for where each kind of text lives.
4. Every file of the theme is **generated by a build** (`@tracy/wordpress-theme`, target
   `tracy-base`) and replaced whole by the next theme update, which the theme fetches by itself
   from its `Update URI`. A hand edit to `theme.json`, `styles/*.json`, `patterns/`, `templates/`,
   `parts/`, `assets/` or `inc/` on the installed site is lost silently. Site-specific overrides
   go where WordPress keeps them: the Site Editor (templates, parts and styles become database
   rows) or a child theme.
5. A section inserted into a page is a **copy**: editing the page changes that page only. The
   seed created **no synced patterns** (`wp_block`); if you create one, editing it changes every
   place that references it. Know which one you are holding before you edit.
6. The header and footer are **database rows** (`wp_template_part` `header` and `footer`, written
   by the seeder to point the navigation blocks at the menus). They shadow `parts/*.html`: editing
   the files changes nothing until the rows are deleted.
7. Do not fabricate business facts, legal text, people, prices or images. Everything on the site
   is demonstration data until the owner replaces it; a gap is recorded, not filled. Read
   docs/content-rules.md.
8. Back up before a structural change (`wp db export`, and `wp-content/uploads`). The quickstart
   is the site **as built**, not a rollback target for an edited site. Read docs/checks-and-recovery.md.
9. Report separately: what changed in files, what changed in the database, which checks ran,
   and what could not be verified.
