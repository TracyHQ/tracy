# JA Morgan: instructions for agents

Read this before changing anything. It describes the **installed WordPress site and its theme**,
not the Tracy skill (`tracy-wordpress-theme`) that produced them.

Theme: **WP Morgan**, slug `wp-ja-morgan`, text domain `wp-ja-morgan`, version in `style.css`
(`Version:` is stamped at build; 1.1.2 when these documents were written). Requires WordPress 7.0
and PHP 8.1; built on WordPress 7.1.2. The site is "Morgan", a business-consulting site ported
from the JoomlArt Joomla 6 quickstart `quickstart/ja-morgan/j6` (template `ja_morgan` on the T3
framework) so that it renders the same pages. No plugin is required by the theme.

## Rules

1. This is a WordPress **block theme**. Templates, parts and patterns are files under
   `wp-content/themes/wp-ja-morgan/`; the site's words are rows in the database. Read
   docs/architecture.md before touching either.
2. Identify the target before any command: `wp option get siteurl`, `wp theme list --status=active`
   (expect `wp-ja-morgan`), the webroot path and the process owner. Never assume a localhost stand.
3. Content is edited **through WordPress** (the editor, `wp post update`, or the REST API) as block
   markup. Do not edit a SQL dump, and do not paste a whole page into one `core/html`. Read
   docs/content-model.md for where each kind of text lives.
4. Every file of the theme is **generated by a build** (`@tracy/wordpress-theme`, target
   `wp-ja-morgan`) and replaced whole by the next theme update (`theme.json`, `patterns/`,
   `templates/`, `parts/`, `assets/`, `inc/` ...): a hand edit is lost silently. Overrides go in the
   Site Editor (database rows) or a child theme.
5. The header, footer and sidebar are theme parts. Once edited in the Site Editor they become
   `wp_template_part` rows that shadow `parts/*.html`; check for such rows before editing a file.
6. A section inserted into a page is a **copy**: editing the page changes that page only. A new
   section goes in from the editor (Patterns > JA Morgan, `wp-ja-morgan/*`); locate its blocks by
   `metadata.name`, never by position.
7. Some behaviour hangs on **slugs and options**, not on blocks: the page slug (`jm-route-<slug>`
   body class, per-style header and colours, listing routes), the 404 text on option
   `wp_ja_morgan_404_page`, the search page on the draft `smart-search`. Read docs/content-model.md
   before renaming, moving or publishing a page.
8. Dark mode: three states kept in the `tracy_theme` cookie and applied as `data-theme` on `<html>`;
   no attribute = auto, the operating system decides (docs/design-system.md).
9. Do not fabricate business facts, legal text, people, prices or images. Everything on the site is
   demonstration data until the owner replaces it; a gap is recorded, not filled. Read
   docs/content-rules.md, which also lists the decisions still open (D-13, D-14, D-15, D-19, D-24,
   D-25, D-26).
10. `wptexturize` is off theme-wide (matches the source): text typed later keeps straight quotes.
11. Back up before a structural change (`wp db export`, `wp-content/uploads`). The theme gets **no
    automatic update offer**; install a newer zip by hand. Read docs/checks-and-recovery.md.
12. Report separately: file changes, database changes, checks run, what could not be verified.
