# Whole-product test strategy for Tracy — the denominator part (W1)

This document is deliberately short. **The truth lives in the JSON files**, not here; when this document and the JSON disagree, the JSON is right.

## What this test suite is

- A person runs it on demand (`pnpm qa <layer>`); it is **not** wired into CI and does **not** run on a nightly schedule.
- Ten layers: `static`, `unit`, `api`, `infra`, `ui`, `flows`, `harness`, `cms`, `mail`, `related`.
- W1 answers only two questions: *what the product has* (the denominator) and *which layers must run when a path changes* (the affected map). W1 does **not** prove anything passed.

## Sources of truth

| Question | File | Generated by |
|---|---|---|
| Which items the product has, which layer each belongs to, which tags it needs | `tests/qa/inventory/inventory.json` | `node tests/qa/inventory/build.mjs` |
| Required edge tags per item kind (verbatim from plan §3) | `tests/qa/inventory/edge-tags.json` | hand-written, checked by selftest |
| Which layer owns each legacy asset (finding, regression, journey, audit item) | `tests/qa/inventory/legacy-map.json` | `node tests/qa/inventory/build.mjs` |
| Changed path → layers that must run | `tests/qa/inventory/affected-map.json` | hand-written; layers chosen by `tests/qa/inventory/affected.mjs` |
| Copy of the old audit data (outside the repo) | `tests/qa/inventory/legacy/*.json` | `extractors/legacy-plan.mjs --import`, `extractors/legacy-findings.mjs --import` |
| Each layer's own denominator | `tests/qa/layers/<layer>/denominator.json` | generated by the layer; merged by `build.mjs` |

Builder pipeline: check arguments (one shared flag parser; an unknown/repeated/empty/whitespace-only flag → exit 2 before any read or write) → check the denominator schema → take a snapshot (two builds must agree) → re-check the whole manifest (input hashes, file lists of dynamic sources, `edge-tags.json`, the set and content of denominators) right before publishing, at most three times → write the pair `inventory.json` + `legacy-map.json` together (all bytes prepared, a recovery copy kept on disk, rolled back on error; if the rollback also fails, say so and keep the `.recover` file). Every read/write path checks each parent component (no symlinks), regular file type, and never hangs on a FIFO.

Drift check: `node tests/qa/inventory/build.mjs --check` exits 1 when a committed file differs from a fresh build (it compares source hashes and every provenance field; only the Git `revision` of in-repo sources is ignored, because a squash/rebase changes the commit without changing the content; the `revision` of an external original is data and is compared, `null` meaning unknown). Selftest: `node --test tests/qa/inventory/test/`.

## Rules that keep the numbers honest

1. Each extractor prints `{ sourcePath, sourceHash, revision, extractionKind, items[], unresolved[] }`. An error, 0 items, a duplicate id or a structure that hides items → that source is `incomplete`, never "silently empty".
2. Only static structure a parser can read (AST, JSON, YAML) is resolved. Routes produced by functions, mounts with a dynamic prefix, spreads from another module, an `NS` not in the file → recorded in `unresolved` with the location; **no guessing**.
3. `inventory.json` has no percentages. A count of items is not coverage. While any source is `incomplete`, `unresolved` or has `unowned` items, the report says so.
4. An item no layer claims (`unowned`) is a real state. The expected ownership in `legacy-map.json` (with its `basis`) is a proposal for a reviewer, and does **not** count as checked or PASS.
5. `N-A` needs a reason **and** a source proving it does not apply: a string `"reason — source"` or an object `{ reason, source }`, where the source is a recognisable reference (file, ADR, §, `#issue`). The validator checks only the structure; it does not prove the N-A argument is right. A layer's denominator is checked against a closed schema; two layers claiming the same item must agree (a tag cannot be required in one layer and N-A in another), each layer claims an item at most once; a claim from a layer other than the item kind's default layer is marked `crossLayer`. Same idea: the legacy sources (audit plan, ledgers S1–S8) go through one provenance validator shared by the importer, the extractor and the selftest — all eight shards, hash, well-formed probe, each finding field of the right type; an old copy is reused only after passing the same validator. Lack of time, lack of an environment, or not knowing the expectation is not N-A. `WAIVED` and `PENDING` are never counted as PASS.

## Reconciliation with the measurements in plan §1

`build.mjs` prints a "planned vs measured" table and stores it in `inventory.json` under `reconciliation`. Everything matches, except:

- **Old audit findings: 158, not 155.** The eight ledgers (`ledger-S1…S8`) declare 158 unique ids (S1=27, S2=21, S3=22, S4=13, S5=18, S6=17, S7=16, S8=24). The brief states 155; the difference has not been checked against enough sources to claim 155 is outdated, so 158 is kept. **Not fully verified:** at the given path only `ledger-S1.md` exists (its hash matches the copy); `ledger-S2…S8` do not exist (probe ENOENT), so 158 is the number the copy declares, not re-checked against the originals. The verified/unverified state and the probe are stored in `legacy/audit-findings.json` (`source.files[].verification`) and shown in the inventory's `unresolved`. The selftest `provenance.test.mjs` compares the hash and every copied field of the ledgers that are available, and prints which ledgers are verified and which are not.
- **Declared API paths 149/272 but only 148/271 have a method**: one path (`/api/sites/{key}/apply/{action}`) in the snapshot has no HTTP method.

## What W1 cannot measure yet (never to be read as "does not exist")

- **dsh runtime graph** (which plugins native/web/desktop actually load): only the bundle declarations exist, recorded as `unresolved: runtime-graph-not-collected`.
- **Storybook index**: 342 is a lexical count of `export const`, not the number of stories Storybook builds.
- **API routes — the route-registration grammar is limited.** The scanner confirms `inCode` only when a route is registered *unconditionally* on a receiver (`new Hono()`) whose mount path leads to the returned receiver (`return app` or `return Object.assign(app, …)`), or to a parameter a helper is passed the app through. Helpers and factories are resolved by binding at the call site (not by name). Not confirmed: functions only declared or exported but never called, callbacks (including named callbacks passed to `forEach`), receivers not connected to the app, chained registration (`app.get().post()`), `basePath`/`mount`, reassigned receivers. Registrations under a condition (`if`, `?:`, `&&`, loops, `switch`, `catch`, after a possible early `return`) are **kept but not confirmed**: the door carries `registeredConditionally: true`, `inCode: false`, and each place has an `unresolved` entry that blocks completion. Most `tracy-web` routes register inside `if (deps.config)`, so most doors are in that state — a real result of the strict grammar, not a bug; doors depending on computed paths (`endpoint`, `UNSUBSCRIBE_PATH`), `/v1/*` through `app[method]`, and `bar/route.js` (used only through `bar.fetch`, never mounted) are in the `unresolved` of `api-doors`, which is therefore `incomplete`. The scanner is not a JavaScript interpreter: structure outside the grammar → `unresolved`, which blocks completion.
- **Plugin string namespaces** with spreads from another module or dynamic keys: the `plugin-strings` source is `incomplete`; the entry is kept with `keysKnown` (the number of visible keys) and `keys: null`; only the number of `strings.ts` files (20) is reported, never a total key count.
- **audit-kit template** (columns REQUIRED/N-A/WAIVED/PENDING, the traceability chain): the original at SHA `660c72ed…` is not on this machine; the columns follow the plan's and the brief's description. Checking each column against the original template stays **PENDING** until W0 provides the source.
- The number of existing test files (1,221) and the related clones are outside W1's extractors.

## Using the affected map

```bash
node tests/qa/inventory/affected.mjs apps/tracy-web/src/seats/route.js packages/ui/tracy-ui/src/tokens.css
```

Prints each path, the chosen layers and the reason. Specific rules are combined; a fallback rule by top-level folder is used only when no specific rule matches; a path that cannot be classified → **UNKNOWN** and every layer runs. It never answers "no related tests".
