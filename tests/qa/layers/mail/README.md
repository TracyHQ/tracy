# Mail layer

Every letter Tracy sends (notification kinds × interface languages, the direct letters), the sign-in code and token flows, preferences, transports and site mail.

```bash
pnpm qa mail [--area X] [--prove-red] [--out DIR]
node tests/qa/layers/mail/generate.mjs [--check]
```

## Footer

Since 06/10/2026 every letter ends `Terms · Privacy · tracy.ai` (`apps/tracy-web/src/mail/templates/README.md`, pinned in `oracles/mail/oracle.json` `footer`). The footer has no case of its own: the `happy-links` case of every letter requires the links to the legal host to be exactly `https://tracy.ai/terms` then `https://tracy.ai/privacy`, each once, each under its own label in the letter's language (`footer.links`, from REG-PR-973), and the text part to end with the same two addresses, and judges the remaining links as before (`machine.mjs` `withoutLegalLinks`). The way back of the footer's "Manage notifications" for a signed-out reader is a door outcome (`QA-API-scenario-root-keeps-source-and-destination`).

## Denominator

`denominator.json` follows the schema every layer shares (`tracy-qa-denominator/v1`): structure in
[`../../contracts/denominator.schema.json`](../../contracts/denominator.schema.json), rules and this
layer's kinds, `meta` and `details` keys in [`../../lib/denominator.mjs`](../../lib/denominator.mjs)
(`LAYER_CONTRACT.mail`), field by field in [`../README.md`](../README.md). Regenerate with
`node tests/qa/layers/mail/generate.mjs`; the generator refuses to write a file the contract rejects.
`details.generatedFrom` hashes the product files read; `details.counts` are the figures the report prints. `meta.planned` lists, per item, the tags a case covers and the tags still open. A reason whose source is not a file is not an N-A: the tag stays required and the claim is listed under `unresolved` (18 obligations today).

## Checks

Checks the mail of Tracy (letters, direct mail, tokens, transport, preferences) against independent
expectations. Cases live in `cases/*.json` (generated by `generate.mjs`), expectations in
`../../oracles/mail/oracle.json`, facts in `../../fixtures/mail/facts.json`.

## Run

```
node tests/qa/layers/mail/generate.mjs --check          # cases and denominator match a fresh generation
node tests/qa/layers/mail/run.mjs --target local --prove-red --out <fresh dir>
node --import tsx --test tests/qa/layers/mail/test/*.test.mjs
```

The layer runs on **fixtures only**: the machine assertions call the real product modules with a
recording pool and a fake transport, SMTP is a loopback socket, and the legacy product suites run as
child processes. The layer owns **no PostgreSQL stand**: a `QA_STAND_DATABASE_URL` is accepted only
when it is exactly `postgres://` or `postgresql://` followed by `[user[:password]@]loopback[:port]/qa_mail_<name>` (`legacy.mjs:68` (`probeDatabase`)):
no query string, so no `host=`/`port=` override; no fragment; no encoded name. Anything else is
refused without connecting, the child gets only the normalized URL, and inherited `DATABASE_URL` /
`TEST_DATABASE_URL` are removed from child processes (`legacy.mjs:214` (`childEnv`)). Output and
ledger stay inside `--out`, which is claimed exclusively (`common.mjs:70` (`claimOutputDir`)); the
red-proof scratch copy is made under `QA_MAIL_ARTIFACTS` or the system temporary directory
(`red.mjs:602` (`makeScratch`)), and a mutant edit may only touch a regular file under the copied product source `apps/tracy-web/src/` (never the copied tests or package.json),
never one reached through its symlinks to the repository (`red.mjs:647` (`copiedFileCheck`)). The write goes through a
descriptor opened without following a link and proven to be the file just checked (`red.mjs:684` (`writeChecked`)), so a path
component swapped for a symlink between the check and the write is refused before anything is written.

Exit codes: 0 all PASS · 1 any FAIL · 2 usage or contract error · 3 only ENV/PENDING.

## Verdicts

- **PASS** — the oracle is independent and pinned, the assertion ran green, and (with `--prove-red`)
  a recorded mutation turned it red on every variant it claims.
- **FAIL** — the assertion ran and the product did not behave as the oracle says. A real product
  FAIL is reported, never adjusted in the test.
- **ENV** — a prerequisite probe failed (loopback socket, database, browser, inbox).
- **PENDING** — not proven: no independent oracle, no RED proof, or a part nobody ran.

## Known limitations

Open follow-ups, none of which blocks the layer (they are outside product truth, safety and
completion of the runner). Line numbers are of this tree.

- **Proof / red-proof bookkeeping.** `red.mjs:787` (`verifyProof`) trusts the control and mutant
  logs written by the same run; there is no signature, so someone with write access to the output
  directory can forge both sides. `red.mjs:876` (`proveRed`) and `red.mjs:953` (`pushProof`) keep
  proofs per assertion, not per product tree revision; the ledger reuse is pinned to file hashes of
  the edited files only.
- **Raw log retention.** `legacy.mjs:207` (`runSuite`) keeps what the reporter protocol records
  (`suite-reporter.mjs`), and stdout/stderr of the child up to the buffer limit; a child that
  floods output past it is reported as a harness error, not retained whole.
- **Nested CLI / config validation.** `index.mjs:778` (`validateRedProof`),
  `index.mjs:806` (`validateMutant`) and `index.mjs:839` (`validateRedProofOptions`) check shapes for the options
  the runner supports; they do not check that a mutation `find` text is meaningful or that an `only`
  selector names a variant the control reaches (that is caught later, by `red.mjs:787` (`verifyProof`)).
  `run.mjs:10` (`main`) parses flags without value-range checks beyond area and case.
- **Ledger / artifact path policy beyond safety.** `common.mjs:42` (`writeAtomic`) and
  `common.mjs:99` (`readRegularBytes`) guard against symlinks and special files; other policy
  (disk quota, concurrent runs sharing a parent directory, permissions of the output) is not enforced.
- **Report integrity.** `index.mjs:967` (`buildCoverage`) and `index.mjs:1018` (`renderReport`)
  count what the run produced; the report and `results.json` are not signed or cross-checked after
  being written.
- **Oracle scope.** `index.mjs:314` (`oracleIneligible`) accepts a pinned source and a ref; it does
  not verify that the cited passage proves the stated invariant. Cases cite the product reads in
  `effects.reads`, not a file:line per assertion.
- **`recordingPool`** (`machine-support.mjs:100` (`recordingPool`)) answers the statements the product issues from
  memory. It does not prove SQL constraints, the real retry schedule or concurrency; those need a
  PostgreSQL stand (no stand: ENV).
- **Agent actions.** `generate.mjs:368` (`rule:no-agent-notification`) marks tags that are not a letter N-A for
  `rule:no-agent-notification`; the event-creation door is not exercised, so the others stay PENDING.
- **Visual receipts.** `sheets.mjs:198` (`verifyReceipt`) needs a human-reviewed receipt; without one
  the contact-sheet cases stay PENDING.
- **Deliverability.** Nothing sends to a real inbox; spam scoring, DKIM/SPF alignment and mail
  client rendering are not checked (`real inbox` prerequisite: ENV).
- **Suite attribution.** Legacy suites are attributed to cases by test name
  (`legacy-red.mjs`), so a test with several checks proves only the part that ran before it stopped.
