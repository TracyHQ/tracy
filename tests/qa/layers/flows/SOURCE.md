# Source notes

## Drivers generalised from the publish pilot

Originals: the four files delivered as task input in `qa-suite-plan/inputs/pilot-drivers/` (the plan directory of this
effort; override the location for the selftest with `QA_FLOWS_PILOT_ORIGINALS`). The selftest recomputes the sha256 of
each original from that directory when it is present and compares it with the table below. The hash of each original at
the time it was brought in:

| Original | sha256 | Here |
|---|---|---|
| `publish-pilot.mjs` | `69da0e276305e857996307f893cabfcad873ec5d212859486b8543af6b22b46e` | `drivers/publish-pilot.mjs` (function of a running stand) + `stand.mjs` (life cycle) + `stand-client.mjs` (sign-in, SQL) |
| `pilot-drive.mjs` | `d55de02f8b7c82beaab3ae5abe303ea257edfd5eb8e93b1aff8aced9f700d17b` | `drivers/pilot-drive.mjs` |
| `red-on-base.mjs` | `9e37851fee87f754e47f7e2034b1a6b3f86c6d303e0df23c9c6b6c36b16813df` | `drivers/red-on-base.mjs` |
| `regression-run.mjs` | `b490e265c76efa54144c4ae95eb912d615f85b6b4d0517ac3c62e35f9fe10c40` | `drivers/regression-run.mjs` |

What changed, and what did not:

- **No machine path, no fixed project.** Playwright is resolved from the workspace install (`createRequire` over
  `package.json` / `apps/tracy-host/package.json`), not from `node_modules/.pnpm/playwright@1.63.0/...`. The project is
  always `tchqa` (a finite pool of site projects, `pool.mjs`), never `tchpublish`.
- **`publish-pilot.mjs`**: the recipe outside the four files (`work/pilot/.env`, compose override, stubs) is gone. The
  stand is generated by `stand.mjs` (env, override, ports, subnet, mounts all under the artifact directory); the build
  happens in a copy of the tree under the artifact directory, never in the worktree. The pilot is now a function that
  needs `stubDir` (the go-live/ingress stubs are **not** shipped) and says PENDING without it.
- **`pilot-drive.mjs`**: only the Playwright resolution and the header changed; the rows it measures are untouched. The
  expectation strings it writes into its rows are **not** used as an oracle by this layer (no approved oracle for publish
  is in this tree: `REG-PR-948-site-publish-flow` is absent). Rows are evidence.
- **`red-on-base.mjs`**: no fixed source list or candidate tests (`--sources`, `--tests`), no `run-required-tests.mjs`,
  output only under `--out`. Logic (derive the base, verify the unpacked tree is the base, require an `ERR_ASSERTION`
  that is not a missing module) is unchanged.
- **`regression-run.mjs`**: takes `--case`, needs `--database-url` for the PostgreSQL step (BLOCKED → exit 3 without it),
  never writes `tests/regression/results` or `.runs`; verdict and logs go to `--out`. Only cases with the S1–S4 shape
  are understood.

The two other files of that directory (`run-required-tests.mjs`, `check-handoff.mjs`) are not brought in.

## The legacy dev E2E suite (`tests/e2e-dev`)

Run unchanged. `adapter/transport.mjs` lists the only source patches applied while its modules load
(`adapter/hooks.mjs`): `dev.mjs` (ssh → local shell, EmDash label check → owned pool), `browser.mjs` (cookie for the
stand origin, not Secure), `J11` (Origin scheme/port). Each patch must match exactly once; the sha256 of the original and
of the patched text is appended to `legacy/provenance.jsonl` when it is applied and copied into `provenance.json`.
`adapter/local-env.mjs` replaces `lib/env.mjs` (origin, site domain, container names, results folder, pool labels).
