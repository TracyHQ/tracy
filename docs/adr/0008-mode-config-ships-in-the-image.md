## Context

The drawing of the **CMS agents** screen raises a question the code cannot answer: *who tunes a mode, and tunes it for
whom?* The screen has a switch labelled `workspace` (scoped to one customer) next to the persona and prompt file
(things that look shared). Two scopes are mixed in one screen, and **the scope decides where to write, while
where to write decides the delay** — so that question cannot be postponed until coding.

Measured on 03/09, the three things that make up a mode live in three different places, each with its own cost:

| Component | Where it can live | What a change requires |
|---|---|---|
| **skill** | tier 100 `<workspace>/.dsh/skills` · tier 300 `/opt/tracy/skills` (image) · tier 400 `$DSH_HOME/skills` (volume) | copy files · **build the image** · copy files, on every lane |
| **preset** (persona + list of rows) | the shipped root in the package (image) · `<dshHome>/.agent-presets` (volume, `includeUserRoot` on by default) | **build the image** · write files, on every lane |
| **tool** | a plugin in the bundle, through the registry | publish + reinstall the profile |

> **Update 26/09/2026 (dsh 0.1.7-rc.2) — the "preset" row of the table above is the 03/09 measurement, now history.**
> Upstream dropped folder-based presets (`d1e22a7e24`): no more shipped root, `roots`,
> `includeShippedRoot`, `includeUserRoot` or `<dshHome>/.agent-presets`. A preset is a
> `@deepseek-ai/dsh-agent-preset` row in the profile; Tracy's 12 presets are generated by `scripts/gen-presets.ts`
> into `presets.patch.yml` of `@tracy/dsh-native-bundle` and `@tracy/dsh-cowork-bundle`, and reach
> customers with the bundle in the image (no more `/opt/tracy/presets`). The only in-place write path left
> is the profile patch (`config-editor`, `plugin-manager`), and both are turned off on the fleet — so
> decisions 2–3 below still hold, only the storage location changes.

Tier 300 and the shipped root are **one copy for the whole fleet**. The volume is **one copy per lane** — cheaper
per round, but multiplied by the number of customers, and no one can answer the question *"are the lanes running the same
skill set"* by looking in one place.

## Decision

1. **The Tracy team tunes modes, not the customer.** The customer has no door to edit the persona, turn rows on/off,
   or add skills to the shared set.
2. **The scope is the whole fleet, and the release path is the image.** Skills go into `/opt/tracy/skills` (tier 300);
   presets go into the package's shipped root (since dsh 0.1.7-rc.2: a `@deepseek-ai/dsh-agent-preset` row in the
   bundle's `presets.patch.yml` — see the note below the table); tools go into the bundle through the registry. One build, every lane gets
   the same set when it is rebuilt.
3. **The volume is not a release path.** `$DSH_HOME/skills` (tier 400) and
   `<dshHome>/.agent-presets` still exist and are still scanned (history: `.agent-presets` stopped being scanned
   from dsh 0.1.7-rc.2, 26/09/2026 — a preset is now only a row in the profile), but they are for two other jobs:
   the dev machine (`scripts/dev-skills.mjs`), and in-place patches during an incident. Using them to release
   creates a fleet where no single place can say what it is running.
4. **Customization for one customer goes through tier 100** — `<workspace>/.dsh/skills` in that customer's own
   workspace, which already beats tier 300 by existing design. That is the path for writing a skill just
   for one customer without forking the library, and it does **not** go through the CMS agents screen.
5. **The CMS agents screen must state that delay.** The text "changes apply to the next session opened" is **wrong**
   as of this decision: a new session in an old lane still reads the old image. The screen says changes go into
   **the next release**, and marks what has not been released yet.

## Accepted costs

- **There is no "save and done" button.** Every persona change or skill addition is a build + container rebuild
  for every lane. This is the most expensive cost and Lee chose it knowingly.
- **An urgent fix for one customer does not go through this screen.** That path is tier 100, or a manual patch on the
  volume that then has to be remembered and brought back into the image — a debt, not a process.
- **Every skill added is context for every customer.** The 53 skills currently enabled are already ≈ 29 thousand tokens of descriptions,
  re-read on every round for every user. The enabled list is a cost decision, not only a feature
  decision — the reason `tracy-enabled.txt` keeps 53 of the 162 available.
- **Rolling back a version means rolling back the image.** This already works: the fleet keeps two stopped containers ready for rollback
  ([`docs/references/profile-map.md`](../references/profile-map.md) §1).

## What this does NOT decide

- **Who in Tracy may press it**, and which surface this screen shows on. Not settled yet.
- **How a `.md` becomes a persona.** `@deepseek-ai/dsh-persona` only accepts `config.text`; the step that reads the
  file and pumps it into `text` when building the preset **has not been written by anyone**. Until it exists, the only way for a
  `.md` to reach the model is to make it a skill, which the model loads when needed rather than having it in the system prompt.
- **The pricing model.** See `CONTEXT.md` §5 — do not infer it from here.
