## Priority 1: consistency, cost and recovery

4. **EmDash writes could proceed after the write-lease door failed — fixed locally in this PR.** `packages/tools/tracy-site-tools/src/host/index.ts` `emdashWriteLease` returns `null` for a missing session or plan and logs then proceeds for any answer other than Stop or `SITE_BUSY` (around lines 3219–3246). This preserves compatibility with older `tracy-web`, but a live web outage can allow two conversations to write without serialization. This PR adds an unavailable-door case, refuses unconfirmed leases, retains the intentional `SITE_BUSY` wait and updates `SYSTEM.md`. Deploy the matching web lease door before the rebuilt dsh image; local tests verify the refusal path, while a real EmDash site acceptance run remains to be done.
5. **A bench budget is checked after answered calls; unknown-cost continuation and an exhausted-budget equality error are fixed locally in this PR.** `agent-over-door.js` refuses the next model call of a budgeted run with `AGENT_BUDGET_UNKNOWN` when an answered call has no known cost, including after resume. It also refuses a new call when known cost equals the budget; the previous strict comparison dispatched another call at that point. Unbudgeted runs continue as before and the cost ledger still marks unknown calls separately. A real DeepSeek call crossed an intentionally tiny USD 0.000001 budget at USD 0.0000276 and the next call was blocked. Provider pricing, input tokens, retries and unknown billing make a hard per-call ceiling unavailable from this guard. Coordinate with #478 and whole-build cost work in #480.
6. **Stop during a bench model call is fixed locally in this PR; provider-settled cost remains unknown.** The shared bench loop now polls the durable Stop request every two seconds, aborts an in-flight model request, and interrupts retry backoff before another attempt. It saves the dispatched turn as a failed, uncertain receipt, because an aborted provider call may already have been billed; the cancelled run is not replayed automatically. Local scripted tests cover the in-flight abort and backoff paths. A real DeepSeek in-flight call returned the local abort 1 ms after Stop was requested 1,503 ms after dispatch. The provider balance precision could not settle that call's charge. Measure a complete Build's Stop-to-termination latency and billed cost before accepting the end-to-end result. The site-editing agent's stopped-write receipt is a separate path and remains unchanged.
7. **Output quality of a picture can be below a passing looker verdict when a frame cannot be hidden; handover provenance is fixed locally in this PR.** The picture fallback may keep the best picture rejected for minor faults so a required frame is not empty (change journal, 6 November). The final `site-write-report.json` now carries `pictureReview`: the frame, source, site path, `filledBy` rung and exact fault names for every `best-rejected` picture. A stratified visual sample by frame role and a stricter acceptance policy for hero, person and offering pictures remain open. Track #336 and #194.
8. **Template and plugin readiness must be an admission rule for the chain.** Missing contract doors, stale content maps, missing baseline measurements or unreleased plugin pins cannot be repaired by a prompt. The readiness verdict detects many cases, but the operational policy for already-live releases differs from a new Publish. Build a CMS × release × plugin-door matrix and only enable chain builds where the required read and write contracts pass. Track #429, #452 and the readiness sections of `SYSTEM.md`.
9. **The write step needs full-site idempotence and read-back.** Open issues cover creating planned pages, hiding every planned item, stable reruns, page settings, link targets and printed alts. An unchanged rerun should produce no new Site changes entry and no demo content on kept pages. Test the complete site, not only a mapping export. Track #352–#379, particularly #374, #375 and #379.
10. **Repair needs an exact fault list and a bounded scope.** The post-write site agent should receive only remaining site-check faults, change only those sites/pages/slots, and be scored by before/after findings. An unresolved finding must remain visible at handover. Track #197, #477 and ADR 0044 section 30.

11. **Effective model readiness is not established by an unassigned door.** The live `/api/ops/llm` response had no assignments for six doors of the proposed Build chain. Source permits an unassigned door to use an environment fallback, so absence of a row is not proof of failure. Add an admission check for each enabled chain step that resolves its effective provider/model and performs the required capability test, including picture looker vision. Record the result per deployment and template before turning on the chain. Do not call the chain ready solely because the ops page and provider entries load.
