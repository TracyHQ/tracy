# i18n — who owns which strings

> **The authoritative source** for the language boundary. **Which words to use** is in
> [`vocabulary.md`](vocabulary.md); **which language to write in** is in
> [`naming-conventions.md`](naming-conventions.md) §5.

## 1. The boundary — decided 2026-08-30

Three parties, and picking the wrong party breaks in three different ways:

| Who | Owns what |
|---|---|
| **dsh** | ~30 namespaces of its own, with `en` and `zh` copies shipped |
| **The community** (`vendor/tracy/dsh-locale-vi`) | The `vi` copy of dsh's namespaces — **and owns the `vi` language itself**: it is the only place calling `ctx.locale.addLanguage()` |
| **Tracy** | Only its own namespaces. The package owning a namespace ships the base `en` copy in `src/client/strings.ts` |

🔒 **Calling `addLanguage` a second time is a duplicate id and crashes the whole plugin tree.** A new language
is added in the package that owns that language, not in `@tracy/dsh-tracy-locale-vi`.

~~**dsh's namespaces are not Tracy's business.**~~ 🔒 **No longer in force since 02/10/2026 (spec #730,
decided by Akemi).** Every language in the Settings › Language menu must be complete on **both sides**: Tracy's
screens and dsh's screens. Tracy still does not re-register dsh's namespaces itself; it fills the gaps **right
inside the package registering that language** (§8). Upgrading dsh can now bring translation work with it: the
`interface-languages` gate will go red on each new sentence.

## 1b. The eight languages Tracy supports — decided 02/10/2026

The single list: [`@tracy/core/interface-languages`](../../packages/core/tracy-core/src/interface-languages/index.mjs).
The menu, language registration and the gate all check against it.

| Language | Who registers the id | Who translates dsh namespaces | Where Tracy namespaces are translated |
|---|---|---|---|
| `en` | dsh | dsh (the source) | the source in `strings.ts` |
| `vi` | `dsh-locale-vi` | `vendor/tracy/dsh-locale-vi/locales/` | `packages/locale/tracy-locale-vi/vi/` |
| `de` `fr` `it` `nl` | the better-locale fork | namespaces better-locale already has: `vendor/tracy/dsh-better-locale/src/client/dictionaries/<lang>.ts`; namespaces it lacks: `packages/locale/tracy-locales/<lang>/` | `packages/locale/tracy-locales/<lang>/` |
| `zh` | dsh | dsh (shipped) | `packages/locale/tracy-locales/zh/` |
| `es` | `@tracy/dsh-tracy-locales` (`languages.json`, calls `addLanguage`) | `packages/locale/tracy-locales/es/` | as in the previous column |

better-locale's 14 other languages are **not registered** (the dictionaries stay in the tree, nobody points to them).
An unregistered language cannot be chosen and cannot win the browser-language detection step.
To add a language back: translate all of Tracy's screens first, only then add it to the list and `languages.ts`.

## 1c. Pages and emails of `apps/tracy-web` — added 02/10/2026 (#753)

`/login`, the code step, the device page, the team/invitation pages, the "no site yet" page, every email and
the `message` of JSON refusals that a plugin shows verbatim: **they do not run in dsh**, so they do not
use `ctx.locale`. They have their own dictionary:

- English source: `apps/tracy-web/src/lib/i18n/strings.js` (`en`, flat dotted keys).
- Translations: `apps/tracy-web/src/lib/i18n/locales/<id>.json`, one key per line, sorted by key.
- The language list is repeated in `WEB_LANGUAGES` (the tracy-web image copies only `src/` and cannot
  import `@tracy/core`); a test and the gate go red if it drifts from `INTERFACE_LANGUAGES`.

**Choosing the language of a request** — the first that answers wins: a valid `?lang=` → a valid
`tracy_lang` cookie → `Accept-Language` (each tag in priority order: exact tag match, then the primary
tag) → English. `zh` is Simplified only: `zh-TW`, `zh-HK`, `zh-MO`, `Hant` do **not** fall back to `zh`.
`<html lang>` follows that language (`zh` is written `zh-CN`, as dsh does).

🔒 **The `tracy_lang` cookie is written only when the user CHOOSES** a language in Settings › Language
(`packages/ui/tracy-settings/src/client/language-cookie.ts`, called from `setLocale` of the Language row),
**never** from the language detected at page load (decided 02/10): for someone who has not chosen, the
sign-in page follows the device. tracy-web only reads this cookie, never writes it.

**Email** follows the language of the request that caused it: the person asking for a code, the person
sending an invitation, the person asking to join a site. The beta queue stores the language in the column
`beta_login_job.lang` (migration 051).
**Exception: notification emails** (Inbox + email, #809) follow the language of the **recipient** —
`account.language`, written by the Inbox poll with `?lang=` (the language currently on screen); outside the 8
languages, or not set yet, English. Why: [`ADR 0026`](../adr/0026-inbox-and-email-notifications.md) §5.

**Gate `web-languages`** (`scripts/check-web-languages.mjs`): every key of `en` must have a non-empty
translation in all seven other languages, the same set of `{placeholder}`s, no extra keys, no em dash,
and a file in canonical form. There is no debt ledger: adding or changing an English sentence means
translating it in the same PR. Sentences for developers/agents (`/v1`, Content API, logs) do **not** go
into this dictionary. (`/ops` has its own dictionary, see §1d.)

## 1d. The `/ops` operations screens — added 26/10/2026

`/ops` (`packages/web/tracy-harness`, a React SPA served at `/ops`) **does not run in dsh**, so it does not use `ctx.locale`,
and it does not use the `apps/tracy-web` dictionary either (that module reads files with `node:fs` and cannot be bundled
for the browser). It has its own dictionary, with the same **eight languages** (`@tracy/core/interface-languages`) and the same
key conventions, `{placeholder}`s, `en` fallback and untranslated terms (§5):

- **Source:** `packages/web/tracy-harness/src/i18n/`. One namespace = `ns/<ns>.ts` (`NS`, `SCREENS` = the screen files it owns, `en`)
  + `locales/<lang>/<ns>.json` for the seven other languages + `fingerprints/<ns>.json`. The full contract is at the top of `i18n/catalog.ts`.
  No shared file lists the namespaces: `import.meta.glob` finds them; each (language, namespace) pair is one lazily loaded chunk.
- **Use:** `const t = useT()` → `t('ns.key', { name })`; `count` picks the plural form through `Intl.PluralRules`;
  `tr()` outside a component; `<Trans>` for sentences with `<b>`/`<a>` tags.
- **Choosing the language:** in order `?lang=` (that page load only) → `tracy.ops.lang` (localStorage, written by the Globe button
  next to the Light/Dark button when the user CHOOSES) → the `tracy_lang` cookie (READ only) → `navigator.languages` → `en`. 🔒 `/ops`
  **never writes or deletes `tracy_lang`**: `clearStaleLanguageCookie` of `@tracy/dsh-settings` deletes that cookie whenever dsh has no
  `preference`, so it cannot be a shared two-way choice between dsh and `/ops`. Accepted consequence: changing the language in `/ops`
  does not change dsh, and the other way round.
- **Translation rules:** translations are data; every language has every key, no em dashes, the terms of `terms.ts` are kept.
  Text Tracy writes for the operator is translated; site/template names, paths, commands, third-party logs, the body of emails sent
  to recipients and agent prompts stay verbatim. Business messages from the server travel as a code + parameters; an unknown code
  shows the original message.
- **Gate `ops-languages`** (`scripts/check-ops-languages.ts`, logic in `scripts/lib/ops-dictionaries.ts`): every key in all seven
  languages, the same `{placeholder}`s and the same `<Trans>` tags, every plural form of each language, no extra keys, a fresh
  fingerprint of each `en` string (changing the meaning of a source sentence means retranslating, then `--accept-sources <ns>`), and
  **no English literal left** in any `SCREENS` file. There is no debt ledger: a screen that has moved over must have all eight
  languages; a screen not moved yet is not gated. The `@tracy/i18n` package (three languages, i18next) is **not** used for `/ops`.

**How far `check-dsh-locale` detects namespaces:** for a namespace missing from `OWNED`, the gate
reports an error if there is a matching JSON file in `packages/locale/tracy-locale-vi/vi/` or it is
recognised by `ownersOnDisk()` from an `NS` declaration in `packages/*/*/src/client/strings.ts`. That function only
recognises declarations matching the regex in [`scripts/check-dsh-locale.ts`](../../scripts/check-dsh-locale.ts).

If a namespace is missing from `OWNED`, has no JSON file in `vi/` and is not recognised by `ownersOnDisk()`,
the two namespace-detection checks report no error for it. That does not prove the whole
gate is green.

For a namespace in `OWNED`, the gate requires the matching `vi/` file and then checks the translation's content. Having both
`OWNED` and a `vi/` file causes no error by itself, nor is it enough to conclude the whole gate is green.

`tracy-settings` is currently in `OWNED`, has `vi/tracy-settings.json` and declares `NS` in
`src/client/strings.ts`. Keep `NS` and `en` there per the convention of §7.

## 3. The mechanism — two halves, and in TCH only one remains

`register(ns, locale, dict)` checks for duplicates **per locale**: `if (locales.has(locale)) throw`.
A namespace that already has `zh`/`en` still accepts `vi` normally → **nothing needs patching**.

The other half — adding `vi` to the locale list — **no longer exists in TCH**, and knowing why matters:

- **On dsh rc.2**, `LOCALES` was an `Object.freeze` constant and `setLocale(id)` **threw** if it did not find the id.
  There was no API to add a locale at run time → the installed dsh had to be patched by a script at image build time.
- **On dsh 0.1.2-alpha.1** — the version TCH runs — there is `ctx.locale.addLanguage()`, and
  `vendor/tracy/dsh-locale-vi` calls it. So when alpha.1 was adopted (30/08/2026), `patch-dsh-locale.mjs` was
  **removed from the Dockerfile and from the repo**, together with the test guarding it and the risk "upgrading dsh turns the build red".

Do not go looking for that script. Any document still mentioning it is a document copied from `tracy-infra` and not yet updated.

🔒 **How the missing half fails, so you recognise it if it comes back:** without `addLanguage`,
`locale.preference: vi` **waits forever** for a definition that never arrives — no error, no log,
just an interface stuck in English.

## 4. Translations are DATA, not code

`vi/*.json` is the source; `lib/client.js` is generated from it by `pnpm dsh-locale:build`.

1. `check-language.ts` scans every string in `packages/` — Vietnamese in a `.js` file is a
   violation. The `vi/` and `en/` directories are exempt **by path**, and `lib/client.js` is exempt
   separately because it is a generated bundle.
2. Readable diffs: one key per line, sorted. On the next upgrade, which strings are new and which are gone is
   **visible**, rather than discovered through an English screen in the middle of a Vietnamese interface.

`lib/client.js` is **committed**: the fleet copies the plugin directory as is and runs no build step there.

## 5. Terms not translated — one list for ALL 8 languages (decided by Brian 05/10/2026)

🔒 **The keep-verbatim list binds every translation: vi · de · it · fr · nl · zh · es.** The single source:
[`packages/locale/tracy-locale-vi/terms.ts`](../../packages/locale/tracy-locale-vi/terms.ts). When a source string
contains a word from it, the translation in **every** language must contain **exactly that word**. The two new labels keep `Sitespace` and `Sitespaces` verbatim; lowercase `workspace` remains an existing term. This decision reverses
Akemi's rule of 02/10/2026 (the list bound only `vi`, the other six languages used native words).

- **The `kept-terms` gate** (`scripts/check-kept-terms.ts`, the deciding part in `scripts/lib/kept-terms.ts`,
  test `scripts/test/kept-terms.test.ts`) guards every catalogue Tracy ships in the seven languages: dsh plugins
  (`tracy-locale-vi`, `tracy-locales` including `dshpw`), the server pages of `apps/tracy-web`, `@tracy/i18n`, and the
  dsh-passwords sign-in cards and pages (`src/locales/*.json`, the `zh` dictionary). The community package `dsh-locale-vi` is not
  guarded; a sign-in page string copied from it that must keep a term becomes Tracy's own translation
  (`gateway.own` in `scripts/test/fixtures/i18n-surface-provenance.json`, with a reason). The `dsh-locale` gate still guards the errors
  specific to `vi` (missing keys, placeholders, untranslated text).
- **Matching is case-insensitive, on ASCII word boundaries**: German "File" passes; the compound
  "Templatevorschau" does not — write "Template-Vorschau". Chinese may place the word between Han characters ("恢复这个 site").
- **18 words added on 05/10:** admin · backup · chat · domain · download · email · folder · link · log ·
  preview · prompt · restore · sandbox · tab · template · terminal · theme · upload.
- **Deliberately still TRANSLATED:** account · password · page · post · draft · publish · menu · media — the words the
  native WordPress/Joomla admin screens use.
- **Known consequence:** third-party dsh translation packs (better-locale for de/fr/it/nl, dsh's `zh` dictionary)
  may still say "Datei", "文件" right next to a Tracy screen saying "File". Tracy does not patch other people's packages.

**Still kept verbatim in EVERY language (as before):** product/platform names (Tracy, WordPress, Joomla,
EmDash, Shopify, GitHub, DeepSeek, Claude, JoomlArt), abbreviations (API, JSON, MCP, URL, CMS, SEO, HTML,
CSS), keys, code, file extensions, `{placeholder}`, slash-command tokens, the confirmation word “Delete”.

**Exception — seat role names ARE TRANSLATED** (Viewer / Editor / Owner, since 08/10/2026): everyday words customers
must understand at once, so they are not on the keep-verbatim list and not exempt in any gate
([ADR 0028](../adr/0028-viewer-editor-owner-roles.md) §7). Admin / Developer were dropped from site seat roles.

The native-word table of 02/10 (Website, Datei, Sitzung, Arbeitsbereich…) is **no longer used** for words on
the list; it only still holds for words outside the list (e.g. seat → Platz/postazione/siège/plaats/席位/puesto).

## 6. Gates

`pnpm dsh-locale:check` (part of `build:check`) catches three **silent** failures — the strings still show,
just wrong:

1. **A missing key** → at run time it falls back to English in the middle of a Vietnamese interface, and nobody reports it.
2. **A mismatched `{placeholder}`** → a dropped one leaves the string missing a name/number; an invented one shows `{name}` for
   users to read.
3. **Translating a word from `terms.ts`**: the source string has that word and the `vi` copy no longer does.

Plus one more check: the `lib/client.js` bundle must not differ from its `vi/*.json` source.

`OWNED` is an **explicit list** in
[`scripts/lib/tracy-owned-namespaces.ts`](../../scripts/lib/tracy-owned-namespaces.ts). The two paths
that detect namespaces missing from this list, and their limits, are described in §2.

### 6.1 Where the gate does NOT reach

- ~~**74 strings hard-coded in dsh's JSX**~~ — the 30/08 measurement on dsh 0.1.2-alpha.1. **Re-measured 02/10
  (#755) on the fork `0.1.7-rc.2-tracy.14`: no customer-visible string remains.** Upstream moved all
  interface text into dictionaries (the decision *locale-owned client UI copy* of 23/08, with dsh's own
  `verify-client-ui-i18n` gate, no allowlist), and Tracy received it when merging rc.2 on
  26/09. The measurement: an AST scan of every string in `src/` of the 46 dsh packages the `native` profile loads, plus a grep of
  the built bundles. Still English, on purpose:
  - **technical error messages** (dsh states the policy *error-surface: not localized*): `unknown or
    malformed command: …` when typing a nonexistent `/` command, `unknown command: /plan off`;
  - **only shown when a plugin turned off in Tracy still runs**: `Stopped because you signed out of DeepSeek.`
    (`dsh-deepseek-account-platform` off);
  - **keyboard-shortcut search keywords** (`new session`, `toggle left sidebar`…): not displayed;
  - **descriptions for agents and developers** (`cordis-client-runner`, `ui-theme`'s token descriptions).
- ~~**`dsh-subscriptions` is not measured.**~~ **Measured since #765.** This package registers
  `locale.register(NS, locale, dictionary)` with `locale` as a variable (a wrapper function called once per
  language: `addLocale('en', en)`), so before that no reader recognised it and nothing warned. Now there is
  a third reader for this shape (§6.2), and the card has all eight languages (`vi` in `dsh-locale-vi`, de/fr/it/nl/es
  in `packages/locale/tracy-locales/<lang>/dsh-subscriptions.json`, `zh` shipped by the plugin itself).
  Since #768 (`0.6.21-tracy.3`) the per-provider token steps, the quota reset time
  and the `/login status` sentence also go through the dictionary (keys `help*`, `reset*`, `loginStatus*`). Still in
  English/Chinese, not yet handled: the quota window names the server sends down (`lib/usage.js` `WINDOW_LABELS`: "5h",
  "7d", "primary", "credits").
- **`node scripts/verify-against-dsh.mjs`** runs dsh's real `LocaleRuntime` on a copy
  in a temp directory. It is **not in `build:check`** and **draws no pixel** — you still have to
  look with your own eyes.

### 6.2 The `interface-languages` gate — every language in the menu, with a debt ledger (since 02/10/2026)

`scripts/check-interface-languages.ts` measures each language shown in the menu, on **Tracy's
namespaces** (`OWNED`, now in `scripts/lib/tracy-owned-namespaces.ts`, shared by the two gates) **and dsh's
namespaces** (the `en` copy read from the built bundle of every client plugin the `native` profile loads, the list
taken from `dsh --dump-config`). Two kinds of hole: missing sentences, and mismatched `{placeholder}`.

**The debt ledger** `scripts/locale-debt.json` records every hole present on the day the gate was turned on. The gate is red when:
- there is a hole **not in the ledger** — a PR adding an English sentence without translating it, or a dsh upgrade bringing new sentences;
- a ledger row **has been translated but not struck** — run
  `pnpm exec tsx scripts/check-interface-languages.ts --strike`;
- a Tracy package translates a dsh namespace that another package **has already registered** for that language (a duplicate registration
  crashes the plugin tree).

`--strike` only **removes** rows, never adds. Adding debt is a hand edit, visible to the reviewer.
Each error points at exactly the file to translate into. A dictionary the first reader (`dsh-locale-vi/tools/lib/extract-en.mjs`)
cannot read goes through the second reader `scripts/lib/dictionary-variables.mjs` (a dictionary spreading another
dictionary `...zoomEn`, comma-joined declarations in a minified bundle). Thanks to that, the image preview, the PDF
preview and the password-gate page (`sidebarImage`, `sidebarPdf`, `dshpw`) have been measured since #755; **there is no longer
an exemption list**: a dictionary both readers give up on turns the gate red.

Since #765 there is a **third reader** (`readWrappedRegistrations`, same file): `locale.register(NS, l, d)`
with the language as a variable, inside a wrapper function the plugin calls once per language (`dsh-subscriptions`).
And a **safety net** (`silentRegistrations`): a bundle containing `locale.register(` from which no reader
can extract an English namespace turns the gate red, unless it is in the gate's `NO_ENGLISH_NAMESPACE` with a
reason (three today: `dsh-locale-vi` and `dsh-better-locale` are translation packs that only register other plugins' namespaces;
`dsh-better-sidebar` is measured separately through `sidebarMissing` and a build-time key-set check). A new
registration shape nobody has taught the readers no longer slips through silently the way `dsh-subscriptions` once did.

The gate ends with `process.exitCode = 1`, not `process.exit(1)`: on macOS, stderr written to a pipe is
asynchronous, and exiting right after a large `console.error` drops everything after the first ~64 KB (906 of
1,246 lines seen, #765).

### 6.3 Two more checks in the `interface-languages` gate (since #740)

- **Bare text in the interface**: English text written directly in JSX or in `aria-label`, `title`,
  `placeholder`, `alt`, `label` is red: no translation can reach it. Since #754 it also catches:
  - text wrapped in braces: `<span>{'Save'}</span>`, `title={'Close'}`, ``title={`Close`}``;
  - **English sentences** (3+ words, capitalised, ending in `.` `!` `?` `…`) assigned to `message`, `error`,
    `title`, `label`, `hint`, `description` or passed to `new Error(...)` / `setError(...)`, including
    in `.ts`/`.mjs` files without JSX. `strings.ts` is exempt (it is the source itself). Files building
    prompts for the agent (read by a model, not a customer) are listed in `AGENT_PROMPT_FILES`, one
    reason per line; a file name no longer in the scan scope turns the gate red.
  - Scope: client code of **every** Tracy plugin (packages with `cordis.patch.yml`), of client libraries
    plugins bundle into their `lib/` (packages exporting `./client`, currently `@tracy/site-build-core`), and all of
    `@tracy/core/src`. Not scanned: `@tracy/ui`, stories, mockups, tests, `lib/`.

  Exceptions with reasons live in the gate's `KEPT_LITERALS` (the unit `px`, the confirmation word "Delete", example
  domain names, an English fallback sentence next to a `t()` key). `@tracy/ui` dialogs require a translated
  `closeLabel`.
- **Direct pushes are measured too**: Tracy CI only runs on PRs, so the `pre-push` hook (`scripts/check-push.mjs`)
  runs this gate when a push into `develop`/`main` touches what the gate measures. On a machine without `pnpm dsh:build` it
  **skips and says plainly** that nothing was measured, without blocking.
- **The debt ledger and `--accept-sources` still rely on the reviewer**: the PR template has a line asking whether the PR edits
  `scripts/locale-debt.json` or runs `--accept-sources`, and why. While the ledger is not empty, each gate run
  prints a `⚠⚠` warning line with the number of debt rows (a warning, not red), so the CI log always shows it.
- **A source sentence whose meaning changed**: `scripts/locale-sources.json` stores a fingerprint of each English
  sentence at the time it was translated. Editing an English sentence and forgetting to retranslate turns it red. After adding or editing sentences, translate into every
  language, then run `pnpm exec tsx scripts/check-interface-languages.ts --accept-sources`.
- Dates and times: use `interfaceLocale()` from `@tracy/core/interface-languages`; do not pass `undefined`.
  A string built from `t()` and then handed to something else to keep (a tab name through `updateTab`) calls `useInterfaceLocale()`
  from `@tracy/core/interface-languages/react` so it is rebuilt when the language changes.

### 6.4 Text written by the HOST (site builds, since #761)

The host does not know which language the reader uses, and does not choose one itself. Two paths:

- **Sentences Tracy writes itself** (details of a stopped build step, the `start` door's refusals): the host writes an English
  sentence (`detail`/`message`) for the log and the agent, together with a **message code** (`detailCode` + `detailParams`,
  or `messageCode` + `messageParams`). The client reads the code through `t('host.<CODE>')` (`hostText` in
  `site-build-core/src/client/host-text.ts`). The English sentence tables: `site-build-core/src/host-messages.mjs`
  (shared) and each plugin's `src/messages.mjs`; `strings.ts` spreads them into the namespace with `hostKeys`,
  so the `interface-languages` gate measures them all. An unknown code or no code shows exactly the sentence the host wrote.
  **Sentences coming from elsewhere** (the site's words, seeder/container output, model sentences) have no code and
  go through verbatim: they are diagnostics, not Tracy's words.
- **Text the host draws into the session itself** (the task list above the composer, retry questions): reads the plugin's
  `words/<lang>.json`, by the language the page sends up (`lang` = `<html lang>`, saved into
  `job.uiLang`), falling back to the conversation's language. The `details` group in `words/` is a **copy**
  of the catalogue's `host.*` lines for retry questions; `test/host-words.test.mjs` keeps the two copies
  equal. Adding a new host sentence = add it to the table, translate it into the catalogue **and** copy it into `details`.

## 7. Adding a new Tracy namespace

1. The owning package declares `NS` and `en` in `src/client/strings.ts`.
2. Add a row to `OWNED` in `scripts/lib/tracy-owned-namespaces.ts`.
3. Add the name to the §2 table of this document.
4. Translate into `packages/locale/tracy-locale-vi/vi/<ns>.json`, run `pnpm dsh-locale:build`.
5. `pnpm dsh-locale:check`, then translate into every language of §1b — the `interface-languages` gate is red
   until it is done.

The namespace name **equals the package name without its scope** (§4 of `naming-conventions.md`) — easy to trace in
`--dump-config`. And it is **vocabulary**: see `vocabulary.md` §5 before coining a new name.
